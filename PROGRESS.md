# RedOx Engine — статус

Обновлено 2026-10-17 (после фазы 5 текстур). Подробный план и журнал выполнения — `docs/ROADMAP_STAGE_0_1.md`,
история изменений — `CHANGELOG.md`, устройство — `ARCHITECTURE_REALITY.md`.

## Готово

- Этап 0 (гигиена): лицензии, линтеры (`clippy -D warnings`, `missing_docs`), `cargo deny`,
  аудит `unsafe` в ECS и Miri, интеграционные тесты, бенчмарки, ADR, документация.
- 1.1 Зависимости: wgpu 30, egui 0.36, rapier 0.36, kira 0.12, glam 0.33, winit 0.30 и др.
- 1.2 Рендер: компилятор графа кадра и декларация кадра (сверяется с кодом тестом), кэш
  пайплайнов на диске (Vulkan), проверка шейдеров при правке и пересборка 11 проходов без
  перезапуска (`Renderer::reload_shaders`), загрузка KTX2/BCn на GPU (`Texture::from_ktx2`).
- 1.3 ECS и ядро: `Commands` (в диспетчере сбрасываются между стадиями), порядок систем
  `before/after`, `run_if`, `par_for_each_mut`, `#[derive(Reflect)]`, состояния приложения с
  `OnEnter/OnExit`, хуки `on_add/on_remove`.
- 1.4 Ассеты: GUID и `.meta`, `.pak` v2 со сжатием LZ4, `AssetSource` (папка/pak), счётчики ссылок
  и выгрузка, зависимости, бюджет завершённых загрузок за кадр, KTX2/BCn, `redox_cook`
  (`pack --compress --incremental`).
- 1.5 Мир и ввод: сохранения (`SaveManager`), `world.bin` (postcard + индекс ячеек), переназначение
  клавиш, контексты ввода, геймпады (gilrs), текст и IME.
- winit: замыкание гоняется через `ApplicationHandler` (`RunClosure`), общих
  `#![allow(deprecated)]` нет.

## Где мы сейчас (2026-10-17)

Этапы 0–1 и план текстур закрыты; код компилируется, тесты, clippy, doc, deny, golden-кадры зелёные.
Остановились после фазы 5 текстур. Примеры: остались `skinned_demo` (он же визуальный регресс),
`dino_runner`, `dino_game`; редактор `redox_editor`. Всё закоммитировано локально, на GitHub не отправлялось, CI нет.
Главные слепые зоны: нет живой проверки глазами, геймпада, IME (другие ОС, GPU и DX12/Metal вырезаны из плана); редактор и рендер почти не покрыты тестами.

## Решение владельца (2026-10-17): следующий курс

Кроссплатформенность и проверка на другом железе вырезаны из планов. Порядок: (1) добивка текстур
(`llvm-cov`, golden-кадры IBL из KTX2 и стриминга, проверка BasisLZ), (2) новый тестовый игровой прототип,
на котором обкатываются анимационный граф, игровой UI и ассеты/стриминг; по итогам прототипа решаем про
скриптинг и редактор.

Пауза (2026-10-17): решение по скриптингу — WASM ([ADR 0005](docs/adr/0005-scripting-wasm.md)). Из добивки текстур
замерено покрытие `redox_asset` (новые модули 80–99 % строк: basis/file 99, ktx2_loader 96, queue 95, stream 89,
pak 87, manager 82, basis/mod 81). Добивка текстур закрыта: покрытие стримера 92 %, IBL 99 %; golden-кадры IBL из KTX2 и стриминга (`redox_render/tests/golden_frames.rs`); BasisLZ на сторонних файлах. Дальше: прототип (анимационный граф, игровой UI).

## Прототип Courier (2026-10-17)

Пример `courier` (`cargo run --release --example courier -p redox_core`) собран на новых частях: анимационный граф
(`redox_anim::graph`: параметры, state machine, blend tree, слои с маской, root motion), игровой UI (`redox_ui::game`:
раскладка, локализация RU/EN с множественными числами, навигация фокусом, стек экранов), уровень и текстуры из `.pak`,
стриминг текстуры земли 2048 px. Проверено тестами (правила игры, риг, раскладка экранов во всех окнах и языках) и
запуском (процесс живёт, паник нет). Не проверено глазами и с геймпадом: ввод геймпада в прототип не подключён,
текстовый ввод и IME не используются. Решение по скриптингу — WASM ([ADR 0005](docs/adr/0005-scripting-wasm.md)), прототип WASM не начат.

## Текстуры KTX2 (готово, 2026-10-17)

- Zstd и Basis Universal (UASTC, ETC1S), кубмапы, массивы, IBL из KTX2 (`redox_cook bake-ibl`),
  приоритетная очередь загрузки, потоковая догрузка mip и `TextureStreamer` с бюджетом памяти.
  План и итоги: [`docs/PLAN_TEXTURES.md`](docs/PLAN_TEXTURES.md), решение: [`docs/adr/0004-ktx2-basis-streaming.md`](docs/adr/0004-ktx2-basis-streaming.md),
  как готовить ассеты: [`docs/ASSETS.md`](docs/ASSETS.md).
- BasisLZ и UASTC+Zstd из сторонних KTX2 (Khronos KTX-Software, 6 файлов) проверены: грузятся, ETC1S и UASTC одной картинки расходятся на 2,2/255. Данные Basis из недоверенных источников защищены контрольными суммами,
  структурными проверками и `catch_unwind`, но C++ транскодер остаётся внешним кодом.

## Отложено (решение владельца, 2026-10-17)

- Горячая перезагрузка compute-части VG (`vg_cull`, Hi-Z) и IBL: состояние нельзя пересоздать на лету, нужен перезапуск.
- Граф кадра: автоматический вывод зависимостей из кода проходов и выделение памяти транзиентных текстур по графу.
- Другие платформы, DX12/Metal, проверка на другом железе — вырезано из плана (2026-10-17), только Windows + Vulkan.

## Не сделано

- Пересборка compute-части VG (`vg_cull`, Hi-Z) и IBL при правке шейдера: нужен перезапуск.
- DDGI на трассировке лучей, SDF-страницы из стриминга, GPU-скиннинг, полный граф Substrate.
- CI не используется (решение владельца); файлы в `.github/` — заготовка, на GitHub не запускались.
- Живая проверка геймпада и IME. Редактор и примеры запускались по 12 секунд без паник и ошибок валидации
  (после исправления падения egui 0.36), но игровая логика и вид кадра глазами не проверялись.

## Покрытие тестами

Замер `cargo llvm-cov` (2026-10-17) по десяти крейтам без GPU и UI: ecs, asset, input, scene, core, anim,
gameplay, physics, math, reflect — **80,1 % строк** (14 025 строк, 2 797 не покрыты), 79,6 % регионов.
Сильные места: ECS `world.rs` 96 %, `pak.rs` 91 %, `rebind.rs` 96 %, `state.rs` в core 97 %.
Слабые: `core/app.rs` 10 % и `window.rs` 0 % (нужен живой цикл окна), `physics/sync.rs` 20 %,
`scene/partition.rs` 61 %, `input/state.rs` 32 %, `math/matrix.rs` и `quat.rs`. Крейты рендера,
редактора, аудио, ui и vfx не измерялись: их основной код требует GPU или окна.

```bash
cargo llvm-cov --summary-only -p redox_ecs -p redox_asset -p redox_input -p redox_scene -p redox_core
```
