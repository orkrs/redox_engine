# Авторинг звука: cue-библиотека, громкость, проверка

Этот документ для звукорежиссёра. Он описывает, как записать `cues.ron`, какие уровни громкости
выбирать, и как проверить файлы и библиотеку до запуска игры.

## 1. Файл `cues.ron`

Файл — RON-список cue. Каждый cue — звуковое событие, которое игра вызывает по имени.

```ron
[
    (name: "step", variants: ["step1", "step2", "step3"], volume: (0.8, 1.0),
     pitch: (0.95, 1.05), cooldown: 0.08, bus: Sfx, priority: 2),
    (name: "hit", variants: ["hit1"], volume: (1.0, 1.0),
     pitch: (0.9, 1.1), cooldown: 0.0, bus: Sfx, priority: 6),
]
```

| Поле | Смысл |
|------|-------|
| `name` | Уникальное имя. Игра вызывает `play_cue("step")`. Пустое имя и дубликат — ошибка загрузки. |
| `variants` | Имена звуковых файлов. Выбирается случайный вариант, без повтора подряд. Список не пустой. |
| `volume` | Линейный множитель `(мин, макс)`, выбирается случайно. Минимум не отрицательный, максимум не больше `4.0` (около +12 дБ). |
| `pitch` | Скорость воспроизведения `(мин, макс)`, `1.0` — исходная высота. Минимум больше нуля, максимум не больше `4.0`. |
| `cooldown` | Секунды до следующего запуска того же cue. Не отрицательно. |
| `bus` | Шина микшера, например `Sfx`. Список шин — в `redox_audio/src/mixer.rs`. |
| `priority` | Важность при нехватке голосов: больше — важнее. Диапазон задаёт тип `u8`. |

Полезные приёмы:

- Одиночный вариант с `pitch: (1.0, 1.0)` звучит одинаково каждый раз. Проверка выдаст
  предупреждение: добавьте вариант или диапазон высоты.
- Два cue с одинаковым набором файлов выдают предупреждение: проверьте, что это не копия.

## 2. Уровни громкости

Цели для `audio-check` по умолчанию (BS.1770, интегральная громкость, LUFS):

- музыка: `-16 LUFS` (`--target-lufs`);
- звуковые эффекты: `-18 LUFS` (`--target-lufs-sfx`);
- допуск: `±3 LU` (`--tolerance`).

Пик не выше `-0.1 dBFS`: при большем значении файл клиппит. Эффект длиннее `10 с` получает
предупреждение: длинные звуки лучше делить на короткие.

Громкость меряется по файлу, поэтому тихий и громкий вариант одного cue могут разойтись. Если
разброс нужен, выставляйте его через `volume` в cue, а не правкой файлов.

## 3. Проверка: `redox_cook audio-check`

```text
redox_cook audio-check <папка-с-звуком> [--cues cues.ron] [--target-lufs -16]
                       [--target-lufs-sfx -18] [--tolerance 3] [--json]
```

Что делает:

- находит все `.wav` и `.ogg` в папке, включая вложенные;
- декодирует каждый файл и печатает пик, RMS, громкость, длительность;
- для файлов в папке с именем `music` (любой регистр, любая глубина) проверяет шов зацикливания:
  разницу уровней в начале и в конце клипа, порог `3 dB`;
- если задан `--cues`, проверяет cue-библиотеку относительно файлов из папки.

Выход: код `1`, если есть ошибка (файл не декодируется или cue-библиотека неверна). Предупреждения
код не меняют. `--json` печатает отчёт одним JSON-объектом: поля `files`, `cues`, `errors`,
`warnings`. Значения, которые не измерены, — `null`.

Формат строки текстового отчёта:

```text
<путь>: <music|sound>, peak <dBFS>, RMS <dBFS>, <LUFS> LUFS, <секунды> s[, seam <dB>]
  <error|warning>: <описание>
cues: <error|warning>: [<cue>] <описание>
<N> file(s), <E> error(s), <W> warning(s)
```

## 4. Звуковая лаборатория (пример без окна)

```text
cargo run -p redox_core --example audio_lab --release -- --cues cues.ron [--assets <папка>]
cargo run -p redox_core --example audio_lab --release -- --selftest
```

- `--cues` печатает список cue и результаты проверки; `--assets` дополнительно ищет файлы в папке.
- `--selftest` проверяет выбор cue (громкость, высоту, cooldown) без устройства вывода.

Окна с вкладками (Cue, Музыка, 3D, Анализ) пока нет.

## 5. Допущения

Эти правила выбраны в коде без подтверждения от движка. Если они не совпадают с вашим конвейером,
поправьте код и этот раздел.

- **Музыка — по имени папки.** Файл считается музыкой, если в пути есть папка `music`. Признака
  зацикливания в формате ассетов пока нет.
- **Окно шва — 50 мс** в начале и в конце клипа.
- **Поиск файла для `--assets` и cue:** имя варианта как есть, затем с `.wav` и `.ogg`.
  Соглашение об именах не сверено с загрузчиком движка.
- **Моно.** Декодер отдаёт всегда стерео. Если оба канала совпадают в каждом кадре, файл меряется
  как моно. Стерео с одинаковыми каналами тоже будет меряться как моно.
- **Уровень тишины — `-120 dBFS`.** Всё ниже этого значения, включая нулевой сигнал, показывается
  как `-120`.
- **Шов — по RMS-уровням,** а не по сэмплам. Фазовый скачок между равно громкими концами не виден.
- **Громкость синуса.** Пример: синус с RMS `-23 dBFS` (пик около `-20 dBFS`) даёт около
  `-23 LUFS`. Синус с пиком `-23 dBFS` даёт около `-26 LUFS`.
