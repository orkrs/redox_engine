# GI-06 — SDF из мира: запекание в cook, загрузка из `.pak`, стриминг по ячейкам

- **Статус:** не начат.

- **Размер:** 5 шагов (S, M, S, M, S) ≈ 9 дней. **Крейты:** `redox_render`, `redox_cook`, `redox_core` (подключение к миру). **Зависит от:** GI-01 шаги 1–2 (`GlobalSdf`, `from_bricks`, `set_gi_static_bricks`). **Блокирует:** —.
- **Модель:** haiku по шагам 1, 2, 3, 5; шаг 4 (стриминг ячеек, `GlobalSdf` как скользящее окно) — haiku с проверкой координатора.
- Закрывает пункт «SDF-страницы — запечённые демо-данные, не связаны со стримингом сцены». **Не входит:** SDF для скинированных и вращающихся объектов, SDF от VG-кластеров.

## Суть и аудит
- `sdf/bake.rs`: `bake_mesh(mesh, world_size) -> DistanceField64` (64³, CPU, брут-форс по треугольникам), `SdfBrick { field, origin_ws, world_size }`. Оффлайн-запекания в cook нет: единственный пользователь — `redox_editor_ui::packager` (демо, заглушки «FAIL needs SdfGpuAtlas»).
- Сцена знает меши и трансформы, но не отдаёт их SDF; GPU-атлас `SdfGpuAtlas` (≤ 8 кирпичей, для теней `sdf_shadow`) и `GlobalSdf` GI-01 ждут кирпичей от игры вручную.
- Мир: `world.bin` (postcard + индекс ячеек), `BinWorld::cells()`, `load_cell` (`redox_scene`). `ActorRecord` не ссылается на геометрию (см. VG-04) — шаг 1 этой спеки опирается на решение VG-04 (`GeometryRef`).

## Шаг 1 — формат `.sdfbrick` и чистые функции (S)
- `redox_render/src/sdf/format.rs`: `write_bricks(&[SdfBrick]) -> Vec<u8>` / `read_bricks(&[u8]) -> Result<Vec<SdfBrick>, SdfFormatError>`; заголовок `b"RSDF"`, версия 1, число кирпичей, затем для каждого `origin_ws`, `world_size`, `min/max` (f32), данные `64³` как `u16` (нормировка расстояния в диапазон `[-D, +D]`, `D = 0.5 * max(world_size)`, квантование `round((d / D + 1) * 32767)`), контрольная сумма CRC32 (**ПРОВЕРИТЬ** есть ли `crc32fast` в `Cargo.lock`; нет — FNV-1a 64 собственным кодом, как в `.rvg`).
- Квантование: `quantize_field(&DistanceField64) -> (Vec<u16>, f32)` и `dequantize` — тесты на ошибку.
Тесты: `a_brick_roundtrips_through_the_file_within_the_quantization_error` (|Δ| ≤ D/32767), `a_corrupted_file_is_rejected` (бит в данных → Err), `an_unknown_version_is_rejected`, `an_empty_brick_list_roundtrips`, `a_truncated_file_is_an_error_not_a_panic`.

## Шаг 2 — `redox_cook bake-sdf` (M)
- Команда `redox_cook bake-sdf <scene-or-world-dir> <out-dir> [--world-size-per-meter 1.0] [--max-world-size 8.0]`: для каждого статического меша (источник — как у `bake-hlod`; в первой версии вход — тестовый формат «меши + трансформы», привязка к реальным акторам — по решению VG-04) считает `bake_mesh` (размер домена = AABB меша × масштаб, не больше `max-world-size` по оси; крупнее — режется на несколько кирпичей по сетке), записывает `<cell_x>_<cell_y>.sdf` (кирпичи ячейки).
- Параллельно по ячейкам (`rayon`, уже в зависимостях), детерминированно (порядок кирпичей по `(x,y,z)`), инкрементально (`--incremental`: пропуск, если хеш входа не менялся — тот же приём, что у `pack --incremental`).
- Объекты с поворотом: кирпичи только в мировых осях → для повёрнутых мешей запекается AABB-эквивалент **в мировой системе** (меш трансформируется в мир, затем `bake_mesh` по мировому AABB); флаг `--world-space` по умолчанию включён.
Тесты (юнит в `redox_cook/src/sdf.rs`): `a_cube_scene_produces_one_brick_per_cube`, `a_big_mesh_is_split_into_bricks_no_larger_than_the_limit`, `the_output_is_deterministic` (два прогона — равные байты), `an_incremental_run_skips_unchanged_cells`, `a_rotated_mesh_is_baked_in_world_axes` (расстояние в точке снаружи повёрнутого куба ≈ эталон ±texel).

## Шаг 3 — загрузка в `GlobalSdf` из пака (S)
- `redox_render`: `Renderer::set_gi_static_bricks_from_pak(&mut self, source: &dyn AssetSource, cells: &[CellId])` или (ближе к слоям крейтов) `GlobalSdfBuilder::add_bricks(&mut self, bricks: Vec<SdfBrick>)` + `Renderer::apply_global_sdf(builder)` — **ПРОВЕРИТЬ** зависимость `redox_render → redox_asset`; если её нет, функция чтения остаётся в `redox_render` на `&[u8]`, а чтение из пака — в `redox_core`.
- Пересборка `GlobalSdf` в фоне (GI-01 шаг 2): добавление/удаление кирпичей ячейки не блокирует кадр.
Тест: `bricks_loaded_from_bytes_produce_the_same_global_sdf_as_in_memory_bricks` (±квантование), `loading_the_same_cell_twice_does_not_duplicate_bricks`.

## Шаг 4 — стриминг по ячейкам: скользящее окно (M)
- Система `gi_sdf_streaming_system` (в `redox_core`, рядом с `hlod_system` из VG-04/`SceneStreaming`): по позиции камеры выбирает ячейки радиуса `R_sdf` (по умолчанию 96 м; параметр `GiStreamingSettings`), подгружает `.sdf` загруженных ячеек, выгружает за пределами `R_sdf + 16` (гистерезис), вызывает пересборку `GlobalSdf` не чаще раза в 0,5 с и только при изменении набора.
- `GlobalSdf` — окно вокруг камеры: `origin` привязан к сетке `voxel * 8` (чтобы не мерцало), при смещении камеры > 16 вокселей окно переезжает, пересобирается в фоне; старый объём работает до готовности нового.
- Бюджет: максимум кирпичей в окне `MAX_BRICKS_IN_WINDOW = 4096`; при превышении — отбрасываются дальние (`log::warn!` один раз).
Тесты (без GPU, логика на чистых функциях): `cells_within_the_radius_are_selected_and_sorted_by_distance`, `hysteresis_prevents_flapping_at_the_boundary` (камера колеблется на границе 100 раз → ≤ 2 смены набора), `the_window_origin_snaps_to_the_voxel_grid`, `the_brick_limit_drops_the_farthest_first`, `a_rebuild_is_not_requested_when_the_set_is_unchanged`.
Тест GPU (`tests/gi_sdf_stream.rs`): `moving_the_camera_across_a_cell_border_updates_the_probe_lighting` (две комнаты в соседних ячейках, свет в первой: при переходе во вторую кадр не пустеет, прежний объём работает, пока новый строится).
