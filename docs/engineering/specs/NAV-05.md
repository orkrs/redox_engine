# NAV-05 — Избегание: уложиться в 1 мс на 200 агентов (замер → причина → исправление)

- **Статус:** не начат.

- **Размер:** 4 шага (S, S, M, S) ≈ 5 дней. **Крейт:** `redox_nav` (+ `redox_core` для системы). **Зависит от:** NAV-04 (избегание работает, цель по скорости не достигнута). **Блокирует:** —.
- **Модель:** haiku по шагам 1, 4; шаги 2–3 — haiku с проверкой координатора.
- Цель из ADR 0007 / NAV-01: **200 агентов < 1 мс на обновление на одном ядре**. Сейчас 9,5 мс (`docs/engineering/notes/nav-spike.md`, бенчмарк `nav.rs`, `#[ignore]`).

## Суть и аудит
`NavWorld::update_agents` (`redox_nav/src/avoid.rs:112`) кладёт позиции и скорости в `landmass::Archipelago`, вызывает `archipelago.update(dt)` и читает желаемую скорость. Всё время внутри `landmass` (поиск пути с переиспользованием, следование по коридору, избегание ORCA через `dodgy_2d`, обновление «соседей» без пространственной структуры по умолчанию?). Известно из spike: стоимость растёт ~квадратично по числу соседей в радиусе; что именно в 9,5 мс — путь, следование или ORCA — **не разложено**. Первый шаг — разложить, не угадывать.

## Шаг 1 — профиль по стадиям (S)
- `redox_nav/benches` или `#[ignore]`-тест `nav.rs::profile_update_agents`: 200 агентов в одной комнате и в лабиринте (две конфигурации из spike), время суммарно и по стадиям. Стадии `landmass` недоступны напрямую → измерить варианты: (а) `update` с отключённым избеганием (`AvoidanceType::None`/`radius → 0`; **ПРОВЕРИТЬ** настройки агента в `landmass 0.9`: `AgentOptions`/`avoidance`), (б) только путь (`set_goal` без движения), (в) полный. Разность даёт стоимость ORCA и стоимость пути.
- Вывод таблицей в `nav-spike.md`: «путь X мс, следование Y мс, избегание Z мс; зависимость от числа агентов (50/100/200/400)». Если разложить стадии нельзя, измерить `dodgy_2d` отдельно (шаг 2) — он публичный крейт.
Тесты (юнит-проверки чистых вспомогательных функций, если они появятся; сам замер — `#[ignore]` с печатью): `the_profile_run_is_deterministic_for_a_fixed_seed`.

## Шаг 2 — быстрые рычаги без смены крейтов (S)
Применять по одному, после каждого — замер и запись в таблицу; оставить только дающее ≥ 15%:
1. `neighbourhood` и `max_neighbours` агента (`AgentOptions`): 10 → 5, `neighbourhood` радиус 3 → 2 м (**ПРОВЕРИТЬ** имена полей `landmass`).
2. Частота: избегание обновлять с шагом 0,05 с (20 Гц) вместо кадра, путь — 0,25 с (аккумулятор в `NavWorld`: `AvoidanceSettings { avoid_hz, path_hz }`; по умолчанию 20/4 Гц), между обновлениями возвращать сохранённую желаемую скорость.
3. Усыпление: агент, у цели или без соседей и без цели, не участвует в обновлении (`set_goal(None)` + малый радиус соседей → пропуск вызовов).
4. Спатиальное разбиение: если `landmass` строит соседей за O(n²) — убедиться, что используется его внутренняя сетка; иначе заранее группировать агентов по ячейкам и подавать только соседей (см. шаг 3).
Тесты: `a_lower_update_rate_still_reaches_the_goal` (200 агентов в лабиринте приходят к целям за ≤ 1,3× времени), `agents_without_a_goal_cost_almost_nothing` (замер / отношение), `the_reduced_neighbourhood_does_not_cause_collisions_in_a_corridor` (число пересечений радиусов за 20 с ≤ прежнего + 10%).

## Шаг 3 — собственный ORCA или пул потоков (M, только если шаг 2 не достиг цели)
Варианты по убыванию простоты (выбор по таблице шага 1, решение записать):
- **Пул потоков (`rayon`)**: `landmass` держит `Archipelago` как `&mut`; параллелить внутри нельзя → разделить мир на независимые «острова» агентов (кластеры по расстоянию > 2·neighbourhood), каждый кластер — свой `Archipelago`? Тяжело. Альтернатива: считать избегание **вне** landmass — взять желаемые скорости (`desired_velocity` из пути) и отдельно вызвать `dodgy_2d::Agent::compute_avoiding_velocity` для всех агентов параллельно (`par_iter`), сосед-список по равномерной сетке (хеш ячеек 2 м). Это уже «`dodgy_2d` напрямую» из ADR.
- Реализация: в `avoid.rs` режим `AvoidanceBackend::{Landmass, Dodgy}` (по умолчанию `Dodgy` после проверки качества); `NavWorld` хранит `Vec<AgentState>`, `grid: UniformGrid`, `step(dt)`: (1) путь через landmass (редко, 4 Гц), (2) сетка соседей, (3) `par_iter` по агентам — ORCA, (4) результат.
- Детерминизм: порядок агентов фиксирован по id; параллельный проход пишет в индексированный выход → результат не зависит от числа потоков (тест).
Тесты: `dodgy_backend_keeps_agents_apart_in_a_corridor`, `the_result_is_independent_of_the_thread_count` (1 vs 8 потоков: равные скорости побитно), `agents_still_reach_the_goal_with_the_dodgy_backend` (лабиринт), `the_uniform_grid_returns_exactly_the_agents_within_the_radius` (юнит против перебора).
