# GI-05 — G5: аппаратная трассировка лучей для DDGI (spike в два дня, затем решение)

- **Статус:** не начат. **Ворота:** шаги 2–4 только если шаг 1 покажет «годится».

- **Размер:** 4 шага (S, M, M, S) ≈ 10 дней (шаг 1 — 2 дня). **Крейт:** `redox_render`. **Зависит от:** GI-01 (текстуры проб, обновление, выборка), GI-02 (радиация карточек — не обязательна). **Блокирует:** —.
- **Модель:** шаг 1 — haiku (маленький пример); шаги 2–4 — haiku с проверкой координатора после каждого шага.
- Цель: «полноценный ray-traced DDGI»: пробы трассируются **аппаратно** (BLAS на меш, TLAS на кадр, ray query в compute); SDF-путь GI-01 остаётся запасным (GPU без RT, динамика не нужна). **Не входит:** отражения через RT (GI-04 остаётся на SDF/карточках), трассированные тени, RT для не-статичных скинированных мешей в первой версии.

## Суть
GI-01 даёт многократные отражения света **программной** трассировкой по SDF. Он грубее (SDF 128³ вокруг камеры, статика, без поворота), но работает везде. Аппаратные лучи точнее: настоящие треугольники, динамические объекты в TLAS, тонкие стены без утечек.
В `PLAN_LIGHTING.md` G5 помечен «опционально» с условием «обязательно проверить, что нужные возможности доступны в используемой версии wgpu». Первый шаг — это проверка, а не код.

## Шаг 1 — spike: доступность ray query в wgpu 30 на целевом железе (S, 2 дня)
Новый пример `crates/redox_render/examples/rt_spike.rs` (не участвует в тестах):
1. Запросить адаптер и проверить `adapter.features()` на `wgpu::Features::EXPERIMENTAL_RAY_QUERY` (**ПРОВЕРИТЬ** точное имя: `grep -rn "RAY_QUERY" ~/.cargo/registry/src/*/wgpu-types-30*/src/features.rs`; в wgpu 30 это может называться `EXPERIMENTAL_RAY_QUERY` / `EXPERIMENTAL_RAY_TRACING_ACCELERATION_STRUCTURE`; записать фактические имена в отчёт). Если фич нет — **остановиться, шаг 1 = «не годится»**, записать вывод адаптера (`adapter.get_info()`, список фич).
2. Если есть: построить BLAS из одного треугольника (`device.create_blas`, `BlasTriangleGeometrySizeDescriptor`), TLAS с одним экземпляром (`create_tlas`), собрать (`build_acceleration_structures`), compute-шейдер с `rayQuery` (WGSL `enable wgpu_ray_query;`, `rayQueryInitialize`, `rayQueryProceed`, `rayQueryGetCommittedIntersection`) бьёт 1024 лучей, результат — число попаданий в буфер; сверить на CPU (треугольник в известном месте → известное число).
3. Замеры: время сборки BLAS на мешах 1k / 100k треугольников, TLAS на 1000 экземпляров (мс, `Instant` вокруг `queue.submit` + `device.poll(Wait)`), время 1 млн лучей (мкс на луч).
4. Таблица в `docs/engineering/notes/rt-spike.md`: «фича есть / нет», «ограничения (размер TLAS, число экземпляров)», «стоимость сборки», «стоимость лучей», вывод **годится / не годится / годится с оговорками**.
Решение судьбы шагов 2–4 принимает координатор по таблице. Если «не годится» — спека закрывается статусом «закрыто по результатам spike», SDF-путь остаётся основным (честно записать в `BACKLOG.md`).

## Шаг 2 — акселерационные структуры сцены (M, если «годится»)
- `src/gi/rt_scene.rs`: `RtScene { blas: HashMap<MeshKey, Blas>, tlas: Tlas, instance_count: u32 }`. BLAS строится при первом появлении меша (позиции + индексы, `PREFER_FAST_TRACE`), для скинированных — отложено (пропуск + предупреждение); TLAS пересобирается каждый кадр из `RenderObject` (модельные матрицы 3×4, `custom_data = индекс материала`), только если набор или матрицы изменились (хеш — переиспользовать подход `batching.rs`).
- Учёт памяти: категория `Buffers`/отдельная «rt_accel» (размеры из `blas.size()`/`tlas.size()` **ПРОВЕРИТЬ** API).
- Флаг `Renderer::set_gi_ray_tracing(bool)`; на устройстве без фич — всегда false с `log::warn!`.
Тесты (GPU, пропуск без фичи): `a_blas_is_built_once_per_mesh`, `the_tlas_follows_a_moved_object` (луч в старое место промахивается, в новое — попадает), `instance_count_matches_the_visible_objects`, `rt_is_off_when_the_feature_is_missing` (юнит: функция выбора).

## Шаг 3 — трассировка проб аппаратными лучами (M)
- `shaders/gi_trace_rt.wgsl`: тот же интерфейс, что `gi_trace.wgsl` GI-01 (выход `ray_data[probe*RAYS+ray]`), но `rayQuery` вместо сферического шага; в попадании — нормаль из индексов/вершин BLAS (**ПРОВЕРИТЬ** доступ к вершинам: нужен отдельный storage-буфер геометрии с общим смещением по `instance_custom_data`; собрать в `rt_scene.rs`: `RtGeometry { vertices, indices, offsets }`), альбедо/эмиссия из материала по `custom_data`, прямое солнце — теневой `rayQuery` с `TerminateOnFirstHit`, многократный отскок — как в GI-01 (прошлый кадр проб) либо радиация карточек (GI-02), если включены.
- Выбор пути: `GiTracer` держит оба пайплайна; `if rt_enabled { gi_trace_rt } else { gi_trace }`; остальное (атлас, обновление, выборка) без изменений.
Тесты (GPU, пропуск без фичи): `rt_and_sdf_agree_on_a_simple_room` (Cornell: освещённость 16 точек SDF vs RT ±15%), `a_thin_wall_does_not_leak_with_rt` (стена 2 см: утечка < 1%), `a_dynamic_cube_blocks_probe_rays_with_rt` (куб двигается — тень в пробах следует; с SDF-путём куб отсутствует), `rt_path_is_not_used_when_disabled` (кадр побитно как GI-01).
