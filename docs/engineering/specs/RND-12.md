# RND-12 — Граф кадра владеет временными текстурами

- **Статус:** не начат (аудит кода 2026-11-15).
- **Размер:** 3 шага (M, M, S) ≈ 8 дней. **Крейт:** `redox_render`. **Зависит от:** RND-09 (шаги 1–2: компилятор, `FrameUsage`, `frame_usage_mismatches`). **Блокирует:** —.
- **Модель:** haiku с проверкой координатора после каждого шага.
- Это оставшиеся шаги 3–5 спеки RND-09. Номер RND-11 в дереве спек свободен как файл, но занят в `KNOWN_LIMITS.md` лимитом 10 000 объектов, поэтому продолжение графа называется RND-12. **Не входит:** многопоточная запись команд, async compute, перенос лимита объектов.

## Суть
`render_graph.rs` строит порядок, времена жизни и слоты. `frame_graph.rs` объявляет проходы, а `renderer/frame.rs` выполняет их методами по `frame_pass_order()`. Текстуры принадлежат `init.rs` и `resize.rs`. `PassResources` нет. Выключенный эффект не отдаёт свою текстуру другому проходу. Шаг 2 RND-09 ещё не видит чтения через bind group, поэтому сверка `frame_usage_mismatches` не считается зелёной целиком.

## Что уже есть
- Компилятор, тест `tests/frame_graph_runtime.rs` (часть с `#[ignore]`).
- `FrameState::touch` в диспетчере проходов.
- Комментарий RND-09: в wgpu нет placed resources, алиасинг — это одна `wgpu::Texture` на несколько логических имён с непересекающимися временами жизни.

## Шаг 1 — дописать учёт обращений (M)
- Каждое чтение, из-за которого сверка шага 2 RND-09 красная (`depth`, тени, кластеры, AO, Hi-Z, пул VSM, backbuffer — список сверить с актуальным `frame_usage_mismatches`, не копировать его вслепую), проходит через `touch` или через обёртку, которую сверка видит.
- `tests/frame_graph_runtime.rs` без `#[ignore]` на пунктах, которые шаг закрыл. Оставшийся игнор назван причиной в одну строку.
Тест: `declared_access_matches_the_frame` на сцене с TAA, туманом и VSM.

## Шаг 2 — пул слотов (M)
- `TransientPool`: одна текстура на слот совместимых описаний (`width`, `height`, `format`, `sample_count`, `mip_level_count`). `usage` — объединение нужных флагов.
- Проход берёт вид из пула. Поля `Renderer`, которые пул заменил, не аллоцируются второй раз.
- `resize` и смена набора эффектов пересоздают только слоты, чьё описание изменилось.
- Выключенный эффект не держит слот, если компилятор выкинул его проход.
Тесты: `two_nonoverlapping_targets_share_a_slot`; `resize_keeps_an_unchanged_slot`; `disabling_fog_drops_its_transient_target`; `a_partial_write_does_not_alias` (правило `write_partial` из RND-09).

## Шаг 3 — отчёт (S)
- `Renderer::frame_graph_report()` печатает слоты, `aliased_saved_bytes` и порядок проходов. Категория `MemoryCategory::Transient` входит в `memory_usage`.
- Абзац в `PLAN_EXECUTION.md` и `CHANGELOG.md`. В RND-09 в статус добавить «шаги 3–5 вынесены в RND-12», тело RND-09 не переписывать.

## Границы
- **Читать:** RND-09, `render_graph.rs`, `frame_graph.rs`, `renderer/frame.rs`, `renderer/frame/usage.rs`.
- **Менять:** создание целей в `init.rs` / `resize.rs` только для тех текстур, которые переехали в пул.
- **Не трогать:** порядок визуального результата. Кадр до и после на фиксированной сцене со всеми эффектами — в допуске 0 на LDR, иначе это регрессия, не «шум алиасинга».

## Проверка
`cargo fmt`, `cargo clippy -p redox_render --all-targets -- -D warnings`, `cargo test -p redox_render --test frame_graph_runtime`, один GPU-кадр сравнения до/после (хеш LDR).

## Для исполнителя
`git merge --ff-only main`. Не переводить на пул цель, которую читает следующий кадр (история TAA, предыдущая глубина, история VSM): у неё время жизни шире одного кадра, для пула она не транзиентная. Сомнение — оставить цель полем `Renderer` и написать имя в отчёт.
