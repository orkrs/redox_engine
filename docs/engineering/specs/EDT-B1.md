# EDT-B1 — Редактор, этап B, срез B1: Outliner и иерархия

- **Статус:** не начат.
- **Размер:** 5 шагов (M, M, M, M, S) ≈ 5 дней. **Крейты:** `redox_ecs`, `redox_editor_core`, `redox_editor_scene`, `redox_editor_ui`, `redox_editor`. **Зависит от:** EDT-A2 (`EntityGuid`, `Parent` по GUID), A3 (`Reparent`, Undo). **Блокирует:** B2 (массовые операции над выделением), B7 (Select из валидации).
- **Исполнение:** агент (haiku) без cargo; координатор компилирует и тестирует после шагов.
- Источник: `EDITOR_PLAN.md` §6 B1; ТЗ §4.1, §23.15–23.16 (часть).
- **Не входит:** Data Layers / World Partition UI (этап E), prefab instances (E), полноценные layout-профили (частично уже в A7).

## Суть
`OutlinerPanel` сейчас — список ячеек/актёров OFPA с текстовым фильтром, без дерева иерархии сцены, reparent, hide/lock и мультивыбора диапазоном. Для `*.scene.ron` нужен Outliner как дерево сущностей с Undo-безопасным reparent и виртуализацией на больших сценах.

## Что уже есть
- `redox_editor_ui/src/outliner.rs`: фильтр строки, `OutlinerAction::{LoadCell,UnloadCell,FocusActor,RevertActor}`, работа через `WorldSession` / `StreamedActor`.
- `redox_ecs::hierarchy`: `Parent`, `Children`, `set_parent` (после A3 — `Reparent` в Undo).
- `Selection` в `redox_editor_core` (primary + set); после A3 — dirty/транзакции.
- `GuidIndex` в `redox_editor_scene`.

## Шаг 1 — модель дерева без egui (M)
- `redox_editor_scene::outliner_model`: `OutlinerNode { guid, name, parent, children, hidden, locked, has_error }`; построение из `World` + `GuidIndex` + компоненты `Name`, `Visibility`/`Hidden`, `Locked` (маркеры в `redox_editor_core` или `redox_scene`, если ещё нет — ввести).
- Группы-папки: сущность с маркером `EditorFolder` (editor-only), без рантайм-логики.
- Фильтры: по имени (подстрока), по имени компонента, по флагу ошибки (из списка guid с ошибками валидации — пока пустой вход).
- Тесты без окна: дерево A→B→C; фильтр по имени; фильтр по компоненту; цикл Parent не допускается при построении (битые рёбра → узел в корне + warning).

## Шаг 2 — reparent и трансформации (M)
- Операции модели: `reparent(child, new_parent, keep_world)` через `UndoStack::Reparent` (A3); отклонение цикла.
- Drag-and-drop в UI вызывает ту же операцию одной транзакцией.
- Тесты: reparent сохраняет мировую позицию при `keep_world`; Undo восстанавливает дерево и локальный трансформ; reparent в потомка — ошибка, мир не меняется.

## Шаг 3 — выделение, hide/lock/isolate (M)
- Мультивыбор: Ctrl+click, Shift+диапазон по видимому списку, «выбрать детей», инверсия.
- Hide / Lock / Isolate: пишут компоненты через Undo; isolate скрывает всех, кроме выделения (одна транзакция «Isolate»).
- Тесты: диапазон выделяет N узлов; hide → сущность не pickable в модели флагов; Undo isolate возвращает видимость.

## Шаг 4 — виртуализация и производительность (M)
- UI рисует только видимое окно списка (egui virtual scroll или эквивалент); модель может держать плоский depth-first список с отступами.
- Тест/замер: сцена 50 000 сущностей (генерация в тесте) — построение модели и «кадр» show с высотой 800px укладываются в порог, записанный в `docs/BENCHMARKS.md` (координатор замеряет; агент пишет каркас `#[ignore]` бенча и не ставит выдуманный порог).
- Тест: при 50k полное дерево виджетов **не** создаётся (проверка через счётчик созданных row-id / mock, либо контракт API `visible_range`).

## Шаг 5 — панель и меню (S)
- `OutlinerPanel` для `Level::Scene` показывает дерево; для `Level::World` сохраняет текущий OFPA-режим (или вкладки Scene/World — выбрать проще: два режима по типу уровня).
- Контекстное меню: Renаме, Duplicate, Delete, Reparent to…, Hide, Lock, Focus.
- Поиск в шапке панели использует модель фильтров.
- Расширить `s16`/новый сценарий: hide+save+load сохраняет hidden (если компонент сериализуется).
