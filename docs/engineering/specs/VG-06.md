# VG-06 — Meshlets: команда редактора и регистрация на GPU

- **Статус:** не начат (аудит кода 2026-11-15).
- **Размер:** 3 шага (M, M, S) ≈ 6 дней. **Крейты:** `redox_editor`, `redox_editor_ui`, `redox_render`. **Зависит от:** VG-01 (`build_vg_asset`), VG-02 (регистрация ассета на `VGSystem`). **Блокирует:** EDT-B6 (инстансы VG в viewport).
- **Модель:** haiku. Шаг 2 — с проверкой координатора на GPU.
- Команда `bake_meshlets` перестаёт быть предупреждением, а запечённый ассет попадает в `VGSystem` устройства viewport. **Не входит:** смена формата кластеров, DAG-обход (VG-07), стриминг страниц VG-03.

## Суть
Палитра команд (`crates/redox_editor/src/commands.rs`, id `bake_meshlets`) пишет в лог «Bake Meshlets not wired yet». Packager (`bake_meshlets`) вызывает `build_vg_asset` на процедурном кубе, кладёт `.rmesh` в `.cache/vg` и в отчёте ставит `gpu_register: FAIL needs VGSystem`. У акторов OFPA в этом пути нет мешей. Пока регистрация отложена, флаг `vg_enabled` нечего рисовать.

## Что уже есть
- `build_vg_asset`, кэш `store_cached` / ключ `cache_key`.
- Тесты GPU уже регистрируют ассет на живом устройстве (`tests/vg_dag_frame.rs`, `tests/mat07_vg_gpu.rs`: `register_dag_asset` и обычный путь мешлетов — **ПРОВЕРИТЬ** имя метода для не-DAG и использовать его, не второй загрузчик).
- `RenderHost` владеет `Renderer` и может достать `VGSystem`.

## Шаг 1 — bake по мешам проекта, не по кубу (M)
- `bake_meshlets` в Packager принимает список мешей (путь glTF/примитив актора). Нет ни одного меша — явная ошибка в статусе, куб не подставлять.
- Команда палитры вызывает этот метод и пишет в лог путь кэша и число мешлетов, не предупреждение «not wired».
- Отчёт `.cache/bake_meshlets.txt` содержит путь источника и `meshlets > 0`.
Тесты без GPU: `bake_rejects_an_empty_selection`; `bake_of_a_cube_mesh_writes_the_cache_and_names_the_source`; `the_command_does_not_log_not_wired`.

## Шаг 2 — регистрация на устройстве viewport (M)
- После успешного CPU-bake `RenderHost` регистрирует ассет в `VGSystem` и ставит один инстанс на трансформ актора.
- Повторный bake того же ключа не плодит второй ассет (тот же id).
- В отчёте строка `gpu_register: ok <id>` вместо `FAIL`.
Тест GPU: `a_baked_mesh_is_visible_on_the_vg_path` (кадр с `vg_use_vis_path` и кадр без меша различаются). `baking_twice_keeps_a_single_asset_id`.

## Шаг 3 — документация (S)
Убрать «not wired» из `ROADMAP_STAGE_0_1.md` §1.4.5 и из текста команды, когда шаг 2 зелёный. `CHANGELOG.md`.

## Границы
- **Читать:** `packager.rs` (`bake_meshlets`), `commands.rs`, `virtual_geometry/runtime`, VG-01, VG-02.
- **Менять:** `packager.rs`, `commands.rs`, мост в `render_host.rs`.
- **Не трогать:** `record_dag_traverse`, cook-формат пака (если кэш `.rmesh` уже читается — его и писать).

## Проверка
`cargo fmt`, `cargo clippy -p redox_editor -p redox_editor_ui -p redox_render --all-targets -- -D warnings`, тесты packager без GPU, GPU-тест шага 2 у координатора.

## Для исполнителя
`git merge --ff-only main`. Не регистрировать ассет на устройстве из `redox_editor_ui`: у панели нет `Renderer`. Регистрация живёт в `redox_editor`, панель только готовит CPU-ассет. Если OFPA по-прежнему не хранит путь меша — bake работает по выделенному glTF в браузере ассетов и это написано в статусе, а не замаскировано кубом.
