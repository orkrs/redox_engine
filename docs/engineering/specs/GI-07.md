# GI-07 — SDF GI в игре и в редакторе: плагин, ресурс, кирпичи сцены

- **Статус:** не начат (аудит кода 2026-11-15).
- **Размер:** 3 шага (M, M, S) ≈ 5 дней. **Крейты:** `redox_core`, `redox_editor`, `redox_render`. **Зависит от:** GI-06 (`GiSdfStreaming`, `GiSdfStreamingPlugin`, `bake-sdf`, `set_gi_static_bricks`). **Блокирует:** —.
- **Модель:** haiku. Шаг 2 (редактор сеет геометрию) — с проверкой координатора на GPU.
- Закрывает пункт FINAL_WAVE «GI-06: подключение системы — 📌» и строку EDT-B3 «редактор не вызывает `set_gi_static_geometry`». **Не входит:** нарезка крупного меша на несколько кирпичей (известное ограничение GI-06), клипмап GI, смена алгоритма трассировки.

## Суть
Стример и команда запекания готовы. `GiSdfStreamingPlugin` объявлен в `redox_core/src/gi_streaming.rs` и ни один `App` его не добавляет. Без ресурса `GiSdfStreaming` система выходит сразу. Пример `courier/showcase.rs` кормит GI аналитическими боксами. Редактор включает тумблер GI, а объёма в мире нет, поэтому картинка не меняется.

## Что уже есть
- `gi_sdf_streaming_system` на `Stage::Render`: камера → `gi_sdf_streaming_step` → `Renderer::set_gi_static_bricks`.
- Ресурс: каталог `<x>_<y>.sdf`, `cell_size`, список ячеек, `GiStreamingSettings`.
- `Renderer::set_gi_static_geometry(&[SdfBox])` для сцен без запечённых кирпичей.
- Пустой срез кирпичей **не** сбрасывает прежний объём (документированное поведение GI-06). Спека это не меняет.

## Шаг 1 — игра подключает плагин и ресурс (M)
- Рядом с `with_audio`: `App::with_gi_sdf(self, dir: impl Into<PathBuf>, cell_size: f32) -> Self`. Метод делает `add_plugin(GiSdfStreamingPlugin)` и в `on_setup` вставляет `GiSdfStreaming`, если в каталоге есть хотя бы один `.sdf`. Каталога нет — плагин стоит, ресурс не вставляется, кадр как раньше.
- Список `available` строится по именам файлов `<x>_<y>.sdf`, не руками в примере.
- `courier`: если рядом с уровнем лежат `.sdf`, боксы `set_gi_static_geometry` не вызываются; кирпичи приходят из системы. Нет файлов — оставить аналитические боксы (пример не ломается).
Тесты: `with_gi_sdf_inserts_the_resource_when_a_cell_file_exists`; `a_missing_directory_does_not_insert_the_resource`; `the_available_list_matches_the_filenames`.

## Шаг 2 — редактор сеет объём из статики сцены (M)
- При сборке кадра viewport: статичные меши сцены (не скелет, не скрытые) дают либо кирпичи из уже запечённого `.sdf` проекта, либо `SdfBox` по AABB меша через `set_gi_static_geometry`, если запечения нет.
- Тумблер GI в редакторе вызывает `set_gi_enabled` **и** этот посев. Выключенный тумблер не оставляет старый объём «включённым вхолостую»: GI-проход не читает объём.
- Один раз за смену набора мешей, не каждый кадр заново с нуля, если набор не менялся.
Тест GPU (`redox_editor` или `redox_render`): `editor_static_boxes_change_the_frame_when_gi_is_enabled` (комната из боксов: кадр с GI и без GI различаются, средняя яркость теневой точки выше с GI). Без адаптера тест пропускается.
