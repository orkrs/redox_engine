# SKY-01 — Небо и лучи света: два расследования (корни, не исправления вслепую)

- **Статус:** не начат.
- **Размер:** 2 расследования (S, S) ≈ 1,5 дня. **Крейт:** `redox_render` (чтение), тестовые файлы. **Зависит от:** ничего. **Блокирует:** SKY-02 (его параметры и приоритеты).
- **Модель:** haiku. Главный результат — отчёт с числами, а не код.
- Источник: `../FOREST_SCENE_FINDINGS.md`, E10; план 5.2.1 и 5.2.2.

## Суть
В сцене `forest` (a) «лесной» HDRI на фоне дал коричневую стену холмов вместо неба; (b) лучи света в froxel-тумане (`sun_scatter`) слабые или невидимые. Нужно найти причины и измерить, прежде чем строить процедурное небо.

## Что уже есть (проверено чтением)
- Фон: `pass/skybox.rs` + `shaders/skybox.wgsl` (полноэкранный треугольник; семплирует куб `t_env` по лучу из `inv_view`/`inv_proj`). Куб строится из equirect в `shaders/equirect_to_cube.wgsl` (`resource/ibl.rs`).
- Установка: `Renderer::set_environment`, `set_skybox` (`renderer/settings.rs:239`), `set_ibl_intensity`.
- Туман: `post/fog_froxel.rs` + `shaders/fog_inject.wgsl` (читает VSM: копия `vsm_lookup` из `pbr.wgsl`; униформа: `scatter` x = сила рассеяния солнца, y = анизотропия, z/w = near/far; `sun_dir`, `sun_color`), `fog_integrate.wgsl`, `fog_composite.wgsl`. Настройки: `post/fog.rs` (`FogSettings`).
- Пример для воспроизведения: `crates/redox_core/examples/forest` (`--shot`, `FOREST_CAM="x y z yaw pitch"`, `FOREST_SKY=<файл>`); файлы HDR: `assets/skybox.hdr`, `assets/forest/phalzer_forest_01_4k.hdr` (последний не в git).

## Расследование A — ориентация equirect (S)
1. Синтетическая карта: `tests/sky_probe.rs` (или встроенный генератор в тесте) создаёт equirect 512×256 f32: небо (верх) синее, земля (низ) зелёная, горизонт жёлтый, на +X красный столб, на −Z белый столб; подаётся в `set_environment`, кадр без объектов с камерой, смотрящей на +X, −Z, +Y, −Y.
2. Прочитать пиксели в центре каждого кадра; сравнить с ожиданием для соглашений: Y вверх, +X вправо, −Z вперёд (камера по умолчанию), без зеркала.
3. Прочитать `equirect_to_cube.wgsl` и найти формулу (u, v) ↔ направление; записать её в отчёт (какая ось где, как перевёрнут v).
4. То же для `assets/forest/phalzer_forest_01_4k.hdr`: кадр вверх (+Y) и вперёд; сравнить с картинкой HDRI (миниатюра: 8 столбцов средних цветов по горизонту и по вертикали, посчитанные скриптом).
- **Результат:** один из исходов: (i) конвертер зеркалит/переворачивает → исправление (максимум несколько строк), тест на гранях куба `equirect_axes_match_the_convention`; (ii) конвертер верен, HDRI действительно содержит стену холмов выше горизонта → отчёт «ошибки нет, источник не подходит», снимок с числами.

## Расследование B — слабые лучи света (S)
1. Тестовая сцена `tests/fog_shafts_gpu.rs` (ignored, печатает числа): плотная туманная среда (density 0,02), солнце низко (высота ~15°) впереди камеры, ряд из 6 тонких колонн (кубы 0,5×0,5×12 м, шаг 3 м) между камерой и солнцем, земля. Три кадра: `sun_scatter` = 0, 0,5, 1,0.
2. Метрика: средняя яркость в полосах между колоннами (свет) против полос за колоннами (тень) на одной высоте экрана; отношение «свет/тень» и его рост от `sun_scatter`.
3. Если отношение ≤ 1,1 при `sun_scatter` = 1: искать причину по списку, фиксируя число для каждого пункта:
   - распределение срезов froxel по глубине и размер ячейки на 10 м, 30 м (**ПРОВЕРИТЬ** константы в `fog_froxel.rs`);
   - попадает ли `vsm_lookup` в разрешённую страницу на ближних срезах (счётчик промахов: временно отладочный вывод в тесте, не в основном коде);
   - ненулевые `sun_dir`/`sun_color` в униформе (в `FogSettings` и в `LightScene` одновременно);
   - влияние экспозиции и порога bloom на итоговую яркость;
   - временное накопление (альфа истории).
4. Отладочный вид «только рассеяние» (по образцу `GiDebug`): если добавить дёшево (< 40 строк), оставить как `FogDebug::ScatterOnly`; иначе описать в отчёте.
- **Результат:** таблица «причина → число → влияние на отношение»; исправление только если одно изменение (константа, знак, порядок) поднимает отношение ≥ 1,5 при `sun_scatter` = 1 без изменения кадров с `sun_scatter` = 0 (побитно прежние); иначе отчёт с рекомендацией для SKY-02 шаг 4.
