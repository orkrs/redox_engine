# VG-02 — Виртуальная геометрия, D2: выбор кластеров DAG на GPU, пошагово

- **Статус:** выполнен только шаг 1 (CPU-эталон, данные); шейдеры обхода (шаги 2–4) не написаны.

- **Размер:** 5 шагов (S, M, M, S, S) ≈ 8 дней. **Крейт:** `redox_render`. **Зависит от:** VG-01 (`ClusterDag`, `cut`, `VGDagAsset`). **Блокирует:** VG-03.
- **Модель:** haiku по шагам 1, 4, 5; шаги 2–3 (шейдер обхода, очереди) — haiku с проверкой координатора после каждого шага.
- Файлы `virtual_geometry/runtime.rs` (790 строк, лимит 800!) и `gpu_cull.rs` — одному исполнителю. **Перед шагом 3 вынести часть `runtime.rs` в `runtime/dag.rs`**, иначе размер превысится.

## Суть
Сейчас GPU-проход (`shaders/vg_cull.wgsl`, `virtual_geometry/gpu_cull.rs`) идёт по плоскому массиву meshlet'ов каждого экземпляра: одна нить — один meshlet, фрустум + конус + Hi-Z по прошлому кадру, второй проход для отвергнутых (`cull_mode` 0/1, `RejectRecord`).
С DAG нужно ходить по иерархии: корни → дети, пока ошибка кластера в пикселях не станет меньше порога; выбранные кластеры идут в тот же indirect-буфер, что и сейчас.

## Что уже есть и сохраняется (проверено чтением)
- Двухфазное отсечение с Hi-Z (`cull_mode`, `RejectRecord { inst_idx, meshlet_idx }`, `record_gpu_cull` / `record_gpu_cull_phase2`, `runtime.rs:580,608`), конус нормалей, плоскости фрустума (`CullParams`).
- Формат выхода: `DrawIndexedIndirectCmd { index_count, instance_count, first_index, base_vertex, first_instance }`, где `first_instance = индекс экземпляра`; visibility buffer пакует `(instance << 16) | triangle_id`, `MAX_VG_INSTANCES = 4096` (`vg_vis.wgsl`). **Формат visibility buffer не менять.**
- `IndirectDrawBuffer` (`indirect.rs`), чтение числа команд с задержкой (`poll_readback`).
- Ограничение: материал берётся как `meshlets[instances[i].meshlet_offset].material_index` — у DAG-ассета один материал на ассет (как и сейчас).

## Шаг 1 — эталон на CPU и данные (S)
- `ClusterDag` из VG-01 + `cut` (CPU-эталон выбора, VG-01 шаг 1) — **уже есть**. Добавить `select_for_instances(dags, instances, eye, ppu, threshold) -> Vec<(instance, cluster)>` (чистая функция, тесты).
- GPU-структура кластера (зеркало WGSL), `DagClusterGpu` (96 байт, кратно 16): поля `DagCluster` + `first_child`/`child_count` (для обхода сверху вниз нужны **дети**; в `DagCluster` хранится `group`, строим индекс детей: `children_of(group) -> range` и `parent_group` у кластера). Добавить в `ClusterDag` метод `children_index(&self) -> (Vec<u32> child_ids, Vec<(u32 first, u32 count)> per_group)`; кластер хранит `group` (создавший его) → его дети — кластеры, чьё `parent` — группа, породившая этот кластер... **Точное соглашение зафиксировать в doc-комментарии**: *дети кластера C = кластеры группы G(C), которая упрощалась в C*. Тест: у каждого не-листового кластера есть ≥ 1 ребёнок, у каждого листа 0; объединение детей по всем кластерам уровня k покрывает все кластеры уровня k−1 ровно по одному разу.
- Тесты:
```rust
#[test] fn every_non_leaf_cluster_has_children_and_leaves_have_none() { /* sphere DAG */ }
#[test] fn the_children_of_one_level_cover_the_level_below_exactly_once() { /* multiset equality */ }
#[test] fn the_instance_selection_equals_the_union_of_per_instance_cuts() { /* 5 instances at different distances */ }
#[test] fn gpu_cluster_layout_is_96_bytes_and_16_aligned() { /* size_of */ }
```

## Шаг 2 — обход иерархии волнами (M, WGSL)
Решение «оптимально»: **многопроходный обход по уровням**, без persistent threads (они недоступны/нестабильны в wgpu). Каждый проход — один `dispatch_workgroups_indirect` по размеру текущей очереди.
Буферы: `queue_a`, `queue_b` — `array<vec2<u32>>` (экземпляр, кластер) вместимостью `MAX_QUEUE = 1 << 20`; счётчики `count_a/count_b` (`atomic<u32>`); `dispatch_args` (3×u32). Инициализация: для каждого видимого экземпляра в `queue_a` кладутся его корневые кластеры.
Шейдер `shaders/vg_dag_traverse.wgsl`: нить берёт элемент очереди; считает `projected_error_px(error, lod_center, lod_radius)` и `projected_error_px(parent_error, parent_lod_center, parent_lod_radius)` в пространстве экземпляра (центр сферы → мировой через `transform`, радиус × `max_scale`, функция `max_scale` уже есть в `vg_cull.wgsl:76`);
- если `parent_error_px <= threshold` — кластер **не нужен** (его заменит родитель выше, он уже выбран ранее): ничего;
- иначе если `error_px <= threshold` — кластер выбран: фрустум-тест + конус + Hi-Z (код из `vg_cull.wgsl` — вынести общие функции `test_sphere`, `test_hiz_occlusion` в `shaders/vg_common.wgsl`, подключаемый обоими, **ПРОВЕРИТЬ** как проект подключает общие куски WGSL: `grep -rn "include\|concat" src/shader`), затем `emit_draw` (как сейчас);
- иначе (`error_px > threshold`) — идти глубже: положить всех детей в `queue_next`.
Корректность условия (`parent_error` большая → выбор родителя) следует из `cut` VG-01; шейдер — зеркало `cut` («держать в синхроне», как `dof.wgsl`).
Глубина: максимум `max_levels` (24) проходов; число проходов — по уровню DAG ассета (CPU знает глубину, пишет в uniform).
Переполнение очереди или буфера команд: **огрубление, а не потеря** — при переполнении `queue_next` кластер рисуется сам (как выбранный), если он сам проходит фрустум (счётчик `overflow_events` для статистики и теста).
Тесты (GPU, `tests/vg_dag_gpu.rs`, пропуск без адаптера; чтение буфера команд через staging, как `gpu_cull.rs::read_command_count`):
```rust
#[test] fn the_gpu_selection_equals_the_cpu_cut_for_a_sphere() { /* один экземпляр, камера на 3 расстояниях, threshold 1px: множество кластеров GPU == cut (сравнивать по (index_offset,index_count) команд) */ }
#[test] fn a_far_instance_selects_only_root_clusters() { /* ... */ }
#[test] fn a_near_instance_selects_leaves() { /* ... */ }
#[test] fn an_instance_outside_the_frustum_selects_nothing() { /* ... */ }
#[test] fn queue_overflow_coarsens_instead_of_dropping() { /* MAX_QUEUE=64 в тестовой сборке: число рисуемых кластеров > 0 и покрытие листьев полное (по cut-эталону с огрублением) */ }
```

## Шаг 3 — отсечение экземпляров и подключение к VGSystem (M)
- Предварительный проход `shaders/vg_instance_cull.wgsl`: на экземпляр — фрустум + Hi-Z по сфере экземпляра (AABB из `bounds_min/extent`), результат — `visible_instances` + счётчик; он же формирует `dispatch_args` и начальную очередь (корневые кластеры экземпляра: `root_offset/root_count` в `VGInstanceData` — **ПРОВЕРИТЬ** место: структура 112 байт, `_pad` один u32; при нехватке добавить поля с изменением раскладки WGSL/Rust/тестов; `meshlet_offset/meshlet_count` DAG-экземпляра можно переинтерпретировать как диапазон корневых кластеров по флагу `flags & FLAG_DAG`).
- `VGSystem`: `register_dag_asset(VGDagAsset, queue) -> Option<VGAssetId>`; `spawn_instance` как раньше; в `prepare_frame`/`record_gpu_cull` — ветка: если есть DAG-экземпляры, выполнить `vg_instance_cull` → цикл `vg_dag_traverse` → тот же `draw_vis_indirect`. Плоский путь для старых ассетов сохраняется (смешанные сцены допустимы).
- Конфиг: `VGConfig::error_threshold_px` (по умолчанию 1.0), `max_dag_levels`.
- Тесты: `a_mixed_scene_draws_flat_and_dag_assets` (golden-подобное сравнение числа непустых пикселей >0 и отсутствие ошибок валидации); `the_flat_path_is_unchanged_without_dag_assets` (`golden_frames`/существующие тесты VG зелёные: `grep -rn "vg" tests/*.rs`).

## Шаг 4 — двухпроходный Hi-Z для DAG (S)
Использовать уже существующий второй проход: кластеры, отвергнутые Hi-Z в обходе, пишутся в `RejectRecord`-аналог (`(inst, cluster)`), после перестройки пирамиды (`record_gpu_cull_phase2`) их проверка повторяется и выжившие добавляются в команды.
Тест: `hiz_rejects_are_retested_after_the_pyramid_is_rebuilt` (кластер за стеной остаётся скрытым; кластер, отвергнутый по устаревшей пирамиде прошлого кадра, но видимый — появляется в том же кадре).
