# VG-03 — Виртуальная геометрия, D3: стриминг страниц кластеров, пошагово

- **Размер:** 6 шагов (S, M, S, M, M, S) ≈ 10–12 дней. **Крейты:** `redox_render` (`virtual_geometry/`), `redox_cook` (шаг 1). **Зависит от:** VG-01, VG-02. **Блокирует:** ничего.
- **Модель:** haiku по шагам 1–3 и 6 (чистая логика); шаги 4–5 (GPU-запросы, заливка) — haiku с проверкой координатора после каждого.
- **Условие запуска:** Gate A4 — на сцене с тяжёлой геометрией память VG действительно не помещается в бюджет или время загрузки неприемлемо. Если оба ограничения не нарушены — **стриминг не нужен**: VG-02 держит весь DAG резидентным. Решение — по замеру (VG-02 шаг 5 + `VGSystem::gpu_bytes`, `runtime.rs:117`); без замера не начинать.

## Суть
Весь DAG модели лежит в видеопамяти целиком. Стриминг делит DAG на страницы фиксированного размера; в памяти всегда есть самый грубый уровень (корень), детальные страницы приезжают с диска по запросам GPU и вытесняются по давности.
Дыр в картинке быть не должно: если страница с потомками не загружена, рисуется кластер выше (его ошибка просто больше порога).

- Диапазонные чтения: `AssetSource::read_range(path, offset, len)` (`redox_asset/src/pak.rs:356,369`), `PakReader::read_range` (331); приоритетная очередь загрузки в `redox_asset` (**ПРОВЕРИТЬ** имя: `grep -rn "priority" crates/redox_asset/src`).

Паттерн переиспользовать, **код не копировать, а вынести общее** только если выйдет просто; иначе новый маленький `PagePool`.

## Шаг 1 — разбиение DAG на страницы в cook (S, чистая функция)
```rust
pub const PAGE_BYTES: usize = 64 * 1024;
/// Page layout of a DAG asset: which clusters live in which page.
pub struct PagePlan { pub pages: Vec<PageSpan>, pub cluster_page: Vec<u32>, pub resident_pages: Vec<u32> }
pub struct PageSpan { pub first_cluster: u32, pub cluster_count: u32, pub bytes: u32 }

/// Packs clusters into pages: clusters of one group never straddle two pages; the root level(s) go to page 0 (resident);
/// sorting by (level desc, group) so coarse levels sit together and a page = neighbouring groups of one level.
pub fn plan_pages(dag: &ClusterDag, bytes_per_cluster: &[u32], page_bytes: usize) -> PagePlan;
```
Правила: каждая группа целиком в одной странице; страница ≤ `page_bytes` (группа больше страницы — ошибка `PageError::GroupTooLarge`, но 4×(64 вершины+124 треугольника) ≈ десятки КиБ — помещается); корневой уровень и **все кластеры с `error * ... ` выше порога резидентности** (по умолчанию: два верхних уровня) — в резидентные страницы.
Тесты (юнит):
```rust
#[test] fn no_page_exceeds_its_size() { /* sphere dag */ }
#[test] fn a_group_never_straddles_two_pages() { /* group id -> page set size 1 */ }
#[test] fn the_root_clusters_are_in_resident_pages() { /* ... */ }
#[test] fn every_cluster_has_exactly_one_page() { /* cluster_page.len() == clusters.len(), all < pages.len() */ }
#[test] fn planning_is_deterministic() { /* ... */ }
#[test] fn an_oversized_group_is_an_error() { /* tiny page_bytes */ }
```

## Шаг 2 — формат файла страниц и чтение (S)
Файл `.rvg` (в `.pak` как обычный ассет): заголовок (магия `RVG1`, версия, число кластеров/страниц, таблица `[offset,len,hash32]` страниц, **резидентная часть** — `ClusterDag` целиком без индексов/вершин + резидентные страницы), затем остальные страницы.
```rust
pub fn write_rvg(asset: &VGDagAsset, plan: &PagePlan) -> Vec<u8>;
pub struct RvgIndex { /* header + page table */ }
pub fn read_index(head_bytes: &[u8]) -> Result<RvgIndex, RvgError>;
pub fn decode_page(bytes: &[u8], index: &RvgIndex, page: u32) -> Result<PageData, RvgError>;   // проверяет hash
```
Важно: **сам `ClusterDag` (узлы без геометрии) всегда резидентен** — на GPU обход идёт по всем узлам, а страницы нужны только для вершин/индексов кластеров.
Тесты: `roundtrip_write_read_page`; `a_corrupted_page_fails_the_hash_not_panics`; `a_truncated_index_is_an_error`; `the_header_can_be_read_with_one_range_read` (длина заголовка известна по первым 16 байтам).

## Шаг 3 — пул страниц и вытеснение (S, чистая логика, без GPU)
```rust
pub struct PagePool { /* capacity pages, resident map page->slot, last_used frame */ }
impl PagePool {
    pub fn new(capacity_pages: u32) -> Self;
    /// Marks `page` as needed this frame. Returns its slot when resident.
    pub fn touch(&mut self, page: u32, frame: u64) -> Option<u32>;
    /// Chooses a slot for a missing page: a free one, else the least recently used page not touched this frame. `None` when all slots are in use this frame.
    pub fn allocate(&mut self, page: u32, frame: u64) -> Option<(u32 /*slot*/, Option<u32> /*evicted page*/)>;
    pub fn is_resident(&self, page: u32) -> bool;
    pub fn resident_count(&self) -> usize;
}
```
Резидентные страницы (шаг 1) в пул **не входят** (всегда загружены отдельно).
Тесты: `a_touched_page_is_resident_after_allocation`; `the_least_recently_used_page_is_evicted`; `pages_touched_this_frame_are_never_evicted`; `a_full_pool_with_everything_touched_refuses`; `evicting_reports_the_old_page`; `touch_of_an_absent_page_is_none`; `capacity_is_respected_over_10000_random_operations` (проптест без крейта: детерминированный генератор SplitMix64 из `redox_audio::cues` не использовать — написать 6 строк локально).

## Шаг 4 — запросы страниц с GPU (M)
- В `vg_dag_traverse.wgsl` (VG-02): кластер, который **выбран бы** (error ≤ порога) или нужен как «потомок для детализации», но чья страница не резидентна (`page_resident[page] == 0` — буфер флагов, `array<u32>` по числу страниц) → атомарно `page_requests[page] = 1`, а вместо него **рисуется родитель** (родитель резидентен по построению: родитель либо в резидентной части, либо запрошен ранее — по правилу порядка загрузки сверху вниз). Реализовать так: при обходе, прежде чем положить детей в очередь, проверить, резидентны ли страницы **всех** детей; если нет — выбрать текущий кластер к отрисовке (он уже имеет геометрию), а страницы детей запросить.
- CPU: каждый кадр читать `page_requests` с задержкой 1–2 кадра (`schedule_readback`/`poll_readback`-образец), сбрасывать буфер, получать список страниц, сортировать по приоритету (ближе к камере — выше; в первой версии — по числу кадров запроса подряд).
- Тесты: чистая часть — `fn pages_to_load(requests: &[u32], pool: &PagePool, budget_pages: usize) -> Vec<u32>` (сначала нерезидентные, не больше бюджета, без дубликатов, детерминированный порядок); юниты на неё. GPU — `tests/vg_stream_gpu.rs`: `a_missing_page_is_requested_and_the_parent_is_drawn` (экземпляр, ни одной детальной страницы в пуле: в буфере запросов появились страницы, команд > 0, ни одна команда не ссылается на нерезидентную геометрию).

## Шаг 5 — заливка страниц (M)
- Поток: `PageLoader` берёт список страниц, ставит чтение `read_range` (на фоновом потоке: **ПРОВЕРИТЬ** есть ли пул воркеров в `redox_asset`), декодирует (`decode_page` — шаг 2), в кадре в рамках бюджета `upload_budget_bytes` (по умолчанию 8 МиБ/кадр) пишет в пул вершин/индексов через `StagingRing`, обновляет `page_resident`, `PagePool`.
- Глобальные буферы вершин/индексов VG — не растущие: отдельные пулы `stream_vertices`, `stream_indices` размером `capacity_pages * PAGE_BYTES`; кластеры в странице адресуют их через `slot * PAGE_BYTES + local_offset` (таблица `cluster_slot_offset` на GPU).
- Бюджет памяти: `VGConfig::stream_pool_mib` (по умолчанию 256) входит в `MemoryBudget`/`MemoryCategory` (`renderer/memory.rs`; **ПРОВЕРИТЬ** категорию — `Buffers`).
- Тесты (GPU): `the_picture_converges_to_the_full_detail` (камера у модели; кадры 1…N: число непустых/сравнение с эталоном «без стриминга»: на кадре N разница ≤ 1/255 по каналу в 99% пикселей); `the_memory_never_exceeds_the_pool` (быстрый пролёт камеры: `resident_count <= capacity` на каждом кадре); `a_corrupted_page_is_skipped_and_rendering_continues` (подмена байт страницы → кадры рендерятся, страница помечена «плохой» и не запрашивается повторно); `eviction_returns_to_the_coarse_level` (камера уходит далеко → страницы вытесняются, кадр без дыр).
