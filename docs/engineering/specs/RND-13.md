# RND-13 — Лимит памяти категории отвергает новую загрузку

- **Статус:** сделано (`try_upload_*`, GI atlas в снимке, тесты).
- **Размер:** 3 шага (S, M, S) ≈ 4 дня. **Крейт:** `redox_render`. **Зависит от:** учёт в `renderer/memory.rs` (`memory_usage`, `set_memory_limit`). **Блокирует:** —.
- **Модель:** haiku.
- Лимит перестаёт быть только пометкой в отчёте. **Не входит:** вытеснение старых текстур, бюджет видеопамяти процесса ОС, стриминг мип.

## Суть
`MemoryBudget` считается по живым ресурсам: меши, текстуры, тени, VG, цветовые цели, постоянные буферы. `set_memory_limit` записывает порог, а `memory_usage` помечает категорию как превышенную. Загрузка при этом проходит. Комментарий в начале `memory_budget.rs` («not wired into the renderer») устарел: снимок в рендерере есть, стоп-крана нет. Отдельно KNOWN_LIMITS GI-02: атлас карточек GI (~64 МиБ) в снимок не входит.

## Что уже есть
- `Renderer::set_memory_limit(category, bytes)`.
- `Renderer::upload_mesh` и загрузки текстур в реестр — точки, где байты прибывают.
- `memory_report` для оверлея.

## Шаг 1 — атлас GI в снимке (S)
- Байты атласа карточек GI добавляются в категорию, которую выберет шаг (Textures или отдельная, если она уже есть в `MemoryCategory`). Двойного учёта с другими текстурами быть не должно.
Тест: `the_gi_card_atlas_is_in_the_memory_report` (после включения GI отчёт содержит эти байты; выключенный GI их не содержит).

## Шаг 2 — отказ в загрузке (M)
- Перед `upload_mesh`, загрузкой текстуры и регистрацией буфера VG: если `used + incoming > limit` категории, функция возвращает ошибку (`Result`), ничего не создаёт на GPU и пишет `log::warn!` один раз на категорию, пока кадр не вызовет `memory_usage` снова после освобождения.
- `limit == None` — поведение как сейчас, успех.
- Уже лежащие ресурсы не выгружаются этим шагом.
Тесты: `an_upload_under_the_limit_succeeds`; `an_upload_over_the_limit_returns_err_and_leaves_the_count_unchanged`; `no_limit_accepts_the_upload`; `a_later_free_allows_the_next_upload`. GPU не обязателен, если байты считаются до создания текстуры; создание мокать нечем — тест с лимитом 0 на категории Meshes достаточен на реальном устройстве и пропускается без адаптера.

## Шаг 3 — документация (S)
Поправить шапку `memory_budget.rs`: снимок подключён, лимит отвергает новую загрузку и не вытесняет старое. Снять или сузить GI-02 в части «атлас вне бюджета». `CHANGELOG.md`.

## Границы
- **Читать:** `memory_budget.rs`, `renderer/memory.rs`, `renderer/assets.rs`, KNOWN_LIMITS GI-02.
- **Менять:** сигнатуры загрузок, которые сегодня возвращают голый индекс. Вызовы в редакторе и примерах обработать: ошибка лимита логируется и объект не появляется, паники нет.
- **Не трогать:** формулы категорий, которые уже верны для мешей и VSM.

## Проверка
`cargo fmt`, `cargo clippy -p redox_render --all-targets -- -D warnings`, `cargo test -p redox_render --test memory_budget --test memory_wiring`.

## Для исполнителя
`git merge --ff-only main`. Не вызывать `process::exit` и не портить кадр чёрной текстурой-заглушкой без записи в лог. Если смена `upload_mesh` на `Result` задевает слишком много примеров — ввести `try_upload_mesh`, а `upload_mesh` оставить обёрткой, которая логирует и возвращает прежний индекс-ошибку, и выбрать один вариант в отчёте, не оба в публичном API навсегда.
