# EDT-B3 — Редактор, этап B, срез B3: Viewport, который показывает движок

- **Статус:** не начат.
- **Размер:** 6 шагов (M, M, M, M, M, S) ≈ 8 дней. **Крейты:** `redox_editor_viewport`, `redox_editor`, `redox_editor_ui`, `redox_render`, `redox_asset` (мост). **Зависит от:** EDT-A1 (viewport crate), A8 (ссылки на меши); движок: AST-01 шаги 3–5 (glTF→renderer), MAT-08, SKY-02. **Блокирует:** B4 (миниатюры на нейтральном фоне), golden UI-тесты.
- **Исполнение:** агент без cargo; координатор GPU-тесты и golden. Если AST/MAT/SKY не в main — остановиться и сообщить (не имитировать меши прокси).
- Источник: `EDITOR_PLAN.md` §6 B3; ТЗ §4.4, §8.
- **Не входит:** mesh/texture editors (D), полный material graph UI (B5), terrain/foliage (D).

## Суть
Viewport рисует **прокси-кубы** и землю; `render_host.rs` явно пишет, что Unlit/Normals/Wireframe для реального пути — заглушки (Lit PBR only / selection tint). Редактор не показывает VG, GI, SDF, небо/IBL. Срез подключает реальные меши/материалы и debug-режимы, опираясь на готовый рантайм движка.

## Что уже есть
- `redox_editor_viewport`: camera, gizmo, picker (GPU ID), brush, `ViewportShading::{Lit,Unlit,Normals,Wireframe}`, quad layout, cube_pass/overlay.
- `redox_editor/src/render_host.rs`: комментарий о незавершённых shading modes; прокси.
- Движок: VSM, GTAO, SSR, fog, TAA, GI, frame_graph; примеры `skinned_demo` / golden.

## Шаг 1 — мост ассетов в viewport (M)
- Загрузка меша/материала по `AssetRef` (A8) в GPU-ресурсы редактора (переиспользовать пути AST-01 / asset manager).
- Сущность с валидным mesh ref рисуется мешом; без ассета — прежний прокси (fallback), в оверлее пометка missing.
- Тесты: headless создание `EditorViewport` + загрузка минимального треугольника (фикстура A7) не паникует; сущность без ref → proxy path.

## Шаг 2 — shading modes на реальном пути (M)
- Unlit / Normals / Wireframe / Roughness / Depth — через debug-варианты пайплайна или debug-view движка; **не** fresnel-имитация на кубах.
- Неподдерживаемый режим на бэкенде → статус «unavailable» с причиной (ТЗ), не «похожий» суррогат.
- Тест: Wireframe и Lit на контролируемой сцене различаются по критерию (например средний luma edge buffer / pixel diff > порога) — GPU-тест как в `redox_core` golden; порог согласован с координатором.

## Шаг 3 — небо, IBL, тогглы GI/SDF/fog (M)
- Подключить SKY-02 / IBL к editor view (не заглушка).
- Debug flags: GI on/off, SDF debug, fog — только если рантайм умеет; иначе unavailable.
- Тесты: флаги сериализуются в `EditorSettings` / session и переживают restart (часть).

## Шаг 4 — snapping и орто-виды (M)
- Snapping: grid (есть), surface, vertex — API в `gizmo`/`picker`; Undo одной транзакцией на drag.
- Ортографические виды в quad (уже задел `QUAD_ORTHO_HALF`) — довести до рабочего top/front/side.
- Тесты: snap-to-grid квантует перевод; surface snap при отсутствии хита не двигает.

## Шаг 5 — скриншот и оверлей статистики (M)
- Команда `viewport_screenshot` → PNG в проект или temp; headless путь для тестов.
- Оверлей: FPS, CPU frame (из `FrameProfiler`), GPU time **только** если `redox_render::profiler` реально измерил; иначе «GPU: n/a».
- Golden: контролируемая сцена → PNG, допуск 3/255 (как в плане); `#[ignore]` до прогона координатора на эталонном GPU.

## Шаг 6 — UI и команды (S)
- Меню View: shading, overlays, toggles, screenshot.
- Палитра команд обновлена; хоткеи F1–F4 работают на реальном пути.
- Документ ограничений в `KNOWN_LIMITS.md`, если VG instances в editor ещё частичны.
