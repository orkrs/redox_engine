# VG-04 — D4: HLOD — упрощённый прокси группы объектов ячейки и плавное переключение

- **Статус:** выполнены шаги 1–3; шаг 2 (цикл запекания) и шаг 4 (рантайм) ждут решения, как актёры ссылаются на геометрию.

- **Размер:** 5 шагов (M, S, S, S, S) ≈ 6–8 дней. **Крейты:** `redox_render` (сборка прокси, `mesh/` или `virtual_geometry/`), `redox_scene` (ячейки), `redox_cook` (команда). **Зависит от:** ничего жёстко (VG-01 не нужен: прокси — обычный меш). **Блокирует:** ничего.
- **Модель:** haiku.
- Объём — «минимум» плана D4: прокси ячейки + dither-переключение. **Не входит:** атлас текстур, импосторы, несколько уровней «ячейка → блок → регион» (отложено; первая версия — один уровень).

## Суть
HLOD заменяет **группу объектов** ячейки мира одним упрощённым прокси на расстоянии, где отдельные объекты неразличимы. Уменьшает число экземпляров и вызовов отрисовки. VG убирает LOD внутри меша, HLOD — число объектов; для объектов вне VG это главное средство.

## Что уже есть (проверено чтением)
- Мировое разбиение: `redox_scene::WorldPartition` (`partition.rs`): `cell_size`, `cell_at(pos)`, `tick(world, viewer_pos)`, загрузка/выгрузка ячеек с гистерезисом (`StreamingConfig { load_radius, unload_radius }`), `StreamedActor { cell, id, kind }` на каждой сущности; `world_bin.rs` (`BinWorld`, `convert_ofpa_to_bin`, `load_cell`).
- Упрощение: `meshopt::simplify` (используется в `virtual_geometry/asset_pipeline.rs:63–100` с `simplify_scale`).
- Размытие переключения: `pbr.wgsl:~696–707` — стохастическое отбрасывание по `alpha` и сине-шумовой текстуре (`if alpha < dither { discard; }`) для `alpha < 0.999` или alpha-test. **ПРОВЕРИТЬ:** умножается ли `alpha` на `color.a` объекта (`model.color`); если да — плавное исчезновение прокси/деталей делается значением `RenderObject::color[3]` без правки шейдера.
- Загрузка/сборка ассетов: `redox_cook` (`pack`, `bake-ibl`) — команда `bake-hlod` по тому же образцу.

## Шаг 1 — сборка прокси (M, чистая функция)
```rust
/// A mesh to merge: world-space triangles with one flat colour.
pub struct HlodInput<'a> { pub positions: &'a [[f32; 3]], pub indices: &'a [u32], pub transform: Mat4, pub color: [f32; 3] }

pub struct HlodParams { pub target_triangles: usize /* 2000 */, pub max_error: f32 /* 0.05 of the cell diagonal */, pub weld_epsilon: f32 /* 1e-4 */ }

pub struct HlodProxy { pub vertices: Vec<[f32; 3]>, pub normals: Vec<[f32; 3]>, pub colors: Vec<[f32; 3]>, pub indices: Vec<u32>, pub source_triangles: usize }

/// Merges the inputs into one mesh, welds, simplifies to at most `target_triangles` (stopping early at `max_error`),
/// and colours every vertex with the area-weighted mean colour of the source triangles around it.
pub fn build_proxy(inputs: &[HlodInput<'_>], params: &HlodParams) -> Result<HlodProxy, HlodError>;
```
Нормали — по граням после упрощения, сглаженные по сваренным вершинам. Цвет — взвешенный средний базовый цвет материала источника (в первой версии цвет материала = `Material::base_color`, текстуры игнорируются).
Невидимые изнутри детали не удаляем (оптимизация — отложена).
Ошибки: `HlodError::{NoInput, Degenerate}`.
Тесты (юнит):
```rust
#[test] fn a_proxy_has_at_most_the_target_triangle_count() { /* 20 кубов -> target 24 */ }
#[test] fn a_proxy_covers_the_bounds_of_its_sources() { /* AABB прокси содержит AABB источников с запасом max_error */ }
#[test] fn the_proxy_is_cheaper_than_the_sum_of_the_sources() { /* proxy.indices.len() < sum(source) */ }
#[test] fn the_colour_is_the_area_weighted_mean() { /* красный большой куб + синий малый -> цвет ближе к красному */ }
#[test] fn building_twice_gives_identical_output() { /* детерминизм побитно */ }
#[test] fn empty_input_is_an_error() { /* NoInput */ }
#[test] fn a_single_small_mesh_below_the_target_is_kept_intact() { /* tri count <= target -> без упрощения: source_triangles == triangles */ }
```

## Шаг 2 — формат и cook (S)
- Файл `.hlod` на ячейку: `RHLD`, версия, ключ ячейки `(i32,i32)`, AABB, число вершин/индексов, массивы позиций/нормалей/цветов(RGB8), индексы u32. Запись детерминирована.
```rust
impl HlodProxy { pub fn to_bytes(&self, cell: (i32, i32)) -> Vec<u8>; pub fn from_bytes(b: &[u8]) -> Result<((i32, i32), Self), HlodError>; }
```
- `redox_cook bake-hlod <world-dir-or-world.bin> <out-dir> [--triangles 2000]`: для каждой ячейки из `BinWorld::cells()` загрузить акторы (`load_cell`), собрать статические меши (**ПРОВЕРИТЬ:** как актор ссылается на меш/материал; если у `ActorRecord` нет ссылки на геометрию — в первой версии `bake-hlod` принимает список «мешей и трансформов» из тестового формата, а привязка к реальным акторам — отдельный шаг, записать в отчёт), построить прокси, записать `<cell_x>_<cell_y>.hlod`.
- Тесты: `proxy_bytes_roundtrip`; `a_truncated_hlod_file_is_an_error`; разбор команды `bake-hlod` (как `Command::Texture` в `redox_cook/src/main.rs`); `cook_writes_one_file_per_cell` (мир из 2 ячеек в памяти).

## Шаг 3 — выбор уровня в рантайме (S, чистая логика)
```rust
/// What the viewer sees for one cell.
#[derive(Clone, Copy, Debug, PartialEq)]
pub enum CellLod { Detail, Proxy, Fading { to_proxy: bool, t: f32 } }

pub struct HlodConfig { pub switch_distance: f32 /* 120 m */, pub hysteresis: f32 /* 10 m */, pub fade_seconds: f32 /* 0.6 */ }

/// Next state of a cell given the distance from the viewer to the cell centre and `dt`.
pub fn step_cell_lod(state: CellLod, distance: f32, dt: f32, cfg: &HlodConfig) -> CellLod;
/// Opacity (0..=1) of the detail objects and of the proxy for a state: Detail (1,0), Proxy (0,1), Fading: detail = 1-t (or t), proxy = the rest.
pub fn opacities(state: CellLod) -> (f32, f32);
```
Правила: из `Detail` в `Fading{to_proxy:true}` при `distance > switch + hysteresis`; из `Proxy` в `Fading{to_proxy:false}` при `distance < switch - hysteresis`; внутри полосы гистерезиса состояние не меняется; `t` растёт на `dt / fade_seconds`, при `t >= 1` — финальное состояние; если во время затухания расстояние пересекло порог в обратную сторону — разворот с текущего `t` (без прыжка непрозрачности); NaN/отрицательные `distance`/`dt` — состояние не меняется.
Тесты:
```rust
#[test] fn a_close_cell_stays_in_detail() { /* ... */ }
#[test] fn a_far_cell_fades_to_the_proxy_and_stays_there() { /* серия шагов */ }
#[test] fn inside_the_hysteresis_band_nothing_changes() { /* distance = switch ± hysteresis/2 */ }
#[test] fn reversing_mid_fade_does_not_jump_the_opacity() { /* opacities до и после разворота отличаются <= dt/fade */ }
#[test] fn the_opacities_always_sum_to_about_one_during_a_fade() { /* detail + proxy == 1 */ }
#[test] fn nan_inputs_do_not_change_the_state() { /* ... */ }
```

## Шаг 4 — отрисовка (S–M)
- Система `hlod_system(world, viewer_pos, dt)` (в `redox_scene` или `redox_core`, **ПРОВЕРИТЬ** слой: `redox_scene` не должен зависеть от `redox_render`; тогда система живёт в `redox_core`): для каждой загруженной ячейки с `.hlod` — состояние `CellLod`, прокси-сущность с `MeshHandle`/`MaterialHandle` (материал «vertex colour», **ПРОВЕРИТЬ** есть ли в `Material` режим цвета вершины; иначе — материал с `base_color` = цвет по ячейке (средний) в первой версии), актёры ячейки получают `color[3] = detail_opacity`; при `detail_opacity == 0` — не рисуются (`visible = false`/исключаются из `FrameRenderObjects`), при `proxy_opacity == 0` — прокси скрыт.
- Прозрачность через `color[3]` приводит к стохастическому отбрасыванию в `pbr.wgsl` (см. выше) — **не** к альфа-смешиванию, порядок отрисовки не нужен.
- Тесты (GPU, `tests/hlod.rs`, пропуск без адаптера; сцена — набор кубов, прокси — один крупный куб): `a_mid_fade_frame_shows_both_without_black_holes` (на кадре с `t=0.5` доля тёмных пикселей внутри прокси-AABB ≤ порога); `no_flash_at_the_switch` (разница средней яркости области между кадрами до/после переключения ≤ 0,05).
- Если переключение не плавное из-за TAA — принять (TAA сглаживает dither).
