## 3. Найденные проблемы в коде (по убыванию важности)

### 3.1 Контроллер персонажа: гравитация не ускоряет падение
`character.rs`: `wish.y -= gravity * dt` — постоянное смещение за шаг, скорость не накапливается. **Измерено** тестом `character_v2.rs`: за 1 с падение
19,99994 вместо ≈ 10. Автоступеней нет (`RapierKcc::default()`), персонаж останавливается перед ступенью 0,2 (x = 0,69). Платформы не переносят. → PHY-01…03.

### 3.2 Паники при создании рендерера
`renderer/init.rs:22, 33, 62` — `expect` на surface/adapter/device. На машине без подходящей видеокарты игра падает без объяснения. → RND-05.

### 3.3 Скиннинговые меши не получают тангентов
`SkinnedGeometry` не хранит тангенты; `DEFAULT_TANGENT = [1,0,0]` на CPU и `TANGENT_WORD` в `skin_compute.wgsl`. Карты нормалей у скиннинговых персонажей освещаются неверно. → ANM-01, RND-01, RND-02.

### 3.4 Нет измерения CPU-времени кадра
Бюджет «CPU ≤ 4 мс» (`PLAN_EXECUTION.md`, п. 1.4) не проверяем. → RND-04.

### 3.5 Учёт памяти неполный
`MemoryCategory::Buffers` пуста. → RND-03.

### 3.6 Контроллер: порядок `tick_physics`
Контроллеры идут **до** шага Rapier (`sync.rs:168`): позиция платформы, видимая контроллеру, отстаёт на кадр. Учтено в PHY-03 (перенос по разности последовательных позиций).

### 3.7 Шарниры без ECS-компонента
Только ручной `add_joint`; идентификатор хранить самому. → PHY-04.

## 4. Проверенные и отклонённые «подозрения» (не баги)
Аудит `unwrap/expect/panic` в `src` до первого `#[cfg(test)]` дал 95 строк, из них в производственном коде осмысленных около 45. Просмотрены:
- `redox_ecs/archetype/column.rs`, `world.rs` — `expect` с обоснованием инварианта (раскладка из Rust-типа, `isize::MAX`); `unsafe` покрыт Miri в CI. Не трогать.
- `redox_asset/pak.rs:218–251`, `redox_scene/world_bin.rs:147–151`, `gpu_cull.rs`, `page_request.rs` — `try_into().expect("4 bytes")` на срезах фиксированной длины, предварительно проверенной (`take(&mut pos, N)?`, заголовок заданного размера). Безопасно; переписывать на `Result` нет смысла.
- `redox_core/dispatcher.rs:265, 470, 507, 515` — внутренние инварианты планировщика («ready queue», «Time resource removed mid-frame»); последний — возможная паника, если пользовательская система удалит ресурс `Time`. Низкий риск, в бэклог не берём (описано здесь).
- `renderer/helpers.rs:236–269` — `try_into().expect("one … per array slot")`: массивы фиксированной длины. Безопасно.
- `renderer/draw.rs:69, 158`, `assets.rs:122` — `expect("fallback material"/"fallback texture")`: резервные ресурсы создаются в `init`; паника возможна только при ошибке самого движка.
- `renderer/frame.rs:92` — `unreachable!` на неизвестный проход графа кадра; тест сверяет граф с кодом.
- Остальные вхождения (редактор, `redox_cook`, тесты внутри `src`) в эту ревизию не входят: утилиты и тестовый код.

Аллокации в горячих циклах: в `character.rs` на каждый шаг создаются `Vec` (`entities`, `results`) и новый `RapierKcc` — несущественно для десятков персонажей;
в `render_frame_into` `visible`/`grouped` выделяются каждый кадр. Измерять после RND-04, до этого не оптимизировать (правило проекта «измеряем до и после»).
