# Финальная волна (11): закрыть всё, кроме сети

Дата: 2026-10-30. Сеть (NET-01/02/03, ADR 0008) отложена владельцем и сюда не входит.
Этот документ — единственный источник порядка. Спеки задач дополнены разделом «Закрытие (финальная волна)».

## 1. Правило закрытия: задача не бывает «в процессе»

Каждая задача заканчивается ровно одним из трёх исходов. Статус «частично» и «не проверено» после финальной волны недопустим.

| Исход | Значок | Условие | Что записывается |
|---|---|---|---|
| Сделано | ✅ | Все тесты шагов зелёные, замер (если есть) в `BENCHMARKS.md` | строка «Статус: ✅» в спеке, запись в `CHANGELOG.md` |
| Отклонено по замеру | ⛔ | Ворота спеки не пройдены (выигрыш меньше порога) | число замера в `BENCHMARKS.md`, строка «Статус: ⛔ отклонено по замеру» |
| Известное ограничение | 📌 | Две попытки агента и одна попытка координатора не дали результата в срок | запись в `docs/engineering/KNOWN_LIMITS.md`: симптом, измеренное число, обходной путь, что нужно для устранения |

**Лимит попыток.** Агент: одна основная попытка плюс одна доработка по моему списку замечаний. Если приёмочный тест после этого красный, задачу берёт координатор (одна попытка, без нового агента). Не получилось — исход 📌 с измеренным числом. Это и гарантирует конец: безвыходных задач нет.

**Что считается «закрыто» для меня как координатора.** Не слова агента, а мой прогон: `cargo fmt`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace --no-fail-fast`, `check_file_sizes.py`, `gen_crates_doc.py --check`, затем коммит.

**Изменение процесса (прошу подтвердить):** агентам финальной волны разрешён `cargo check -p <крейт> --all-targets` в их worktree (тесты и clippy по-прежнему только у меня). Именно запрет на компиляцию породил хвосты «написано, не собрано» в волнах 7–10 (RND-09 шаг 3, PST-03/06/07, MAT-02 шаги 4–6, RND-08 шаг 4). Без этого разрешения волна снова даст такие хвосты.

## 4. Расписание

| Раунд | Параллельно | Что делаю я |

| 1 | R1, P, N, S | пишу и проверяю спеки; ставлю цель wasm; принимаю по очереди |
| 2 | R2, A, M | слияние R1/P/N/S, полный прогон, коммит |

| 6 | R6, затем R7 | слияние R5 |
| 7 | R8 | слияние R6/R7 |
| 8 | R9, затем R10 | слияние R8 |
| 9 | R11 (по воротам) | слияние R9/R10 |
| 10 | — | итоговая приёмка, обновление `PLAN*`, `BACKLOG`, `KNOWN_LIMITS`, push по вашему слову |

Это десять раундов, потому что рендерер — узкое место: в одном кадре его правят PBR, граф кадра и пассы материалов. Параллельные дорожки сокращают время только вне рендерера. Быстрее не получится без риска конфликтов.

## 5. Что после финальной волны остаётся вне плана (честно)

- Сеть (NET-01/02/03).
- Не охваченное спеками (см. `BACKLOG.md` §7): редактор как инструмент, собственный UI-бэкенд, мир F1–F5, D5, «полное» E.
- Всё, что получит исход 📌: список — в `KNOWN_LIMITS.md`, наполняется по ходу.
- Живая проверка владельцем (QA-01): звук/геймпад, меню, F5.

Критерий конца волны: по каждому ID из §3 стоит ✅, ⛔ или 📌, а `cargo test --workspace` зелёный.
