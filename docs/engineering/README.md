## Как взять задачу (инструкция исполнителю)
1. Прочитай **только** свою спецификацию и файлы из её раздела «Читать». Остальной репозиторий не изучай.
2. Первым шагом `git merge --ff-only main` (рабочая копия агента создаётся от старого коммита). `Cargo.lock` в `.gitignore`: координатор копирует его из `main` в worktree, иначе зависимости резолвятся заново и могут не собраться.
3. Проверь «Зависит от»: если зависимость не в `main` — остановись и сообщи.
4. Сначала тесты (красные), потом код. Тесты из спецификации не ослабляй; если число из спецификации физически не достигается —
   остановись и сообщи измеренное значение (это ценнее «зелёного» отчёта).
5. Менять можно только файлы из раздела «Менять». Если нужно больше — остановись и опиши.
6. Cargo: не запускай `cargo test --workspace`; только команды из раздела «Проверка». В крейте одновременно работают не больше двух агентов.
7. Перед коммитом: `cargo fmt --check`, `cargo clippy -p <крейт> --all-targets -- -D warnings`. После `git cherry-pick`/слияния — `git status` и `grep -rn "<<<<<<<" crates`.
8. Коммит локальный, формат `<тип>: <описание>` (feat, fix, test, refactor, docs). Не пушить.
9. Отчёт: что сделано, какие команды запущены и их итог, что не проверено.

## Правила проекта (кратко)
Windows + Vulkan (wgpu), без `unwrap` в библиотечном коде, ошибки через `Result`, `missing_docs` — документировать публичное, файлы ≤ 800 строк,
принцип «оптимально, не идеально» (`PLAN_EXECUTION.md` §1), числа всегда измеряем.
