## Решения (по одной строке)

1. `AutosaveService` работает только через трейты `AutosaveSource` и `Clock` из спеки. Зависимости от других `redox_editor_*` нет. Добавлены `redox_scene`, `flume`, `ron`, `serde` в `redox_editor_core`.
2. Счётчик транзакций передаётся аргументом `tick(&source, transactions: u64)`. Сейчас в приложении это `UndoStack::len()`, см. ПРЕДПОЛОЖЕНИЯ.
3. Снимок сериализуется в байты на главном потоке (`snapshot_bytes`), на фоне только пишется файл. Клонирование `WorldSnapshot` не делается.
4. Фоновая запись: `flume`-канал и поток `redox-autosave`. Повтор записи до 3 раз с паузой 50 мс. Ошибка идёт в журнал, цикл пропускается.
5. Политика клампится: интервал 10–3600 с, `every_n_transactions` 1–10 000, `keep` 1–20.
6. Закрытие: при чистом уровне удаляются `session.lock` и автосохранения уровня. При грязном уровне они остаются, и следующий запуск предложит восстановление. Окна «сохранить/не сохранять» при закрытии нет: в приложении ещё нет Save (EDT-A2).
7. Heartbeat пишется через `write_atomic`, поэтому рядом появляется `session.bak`, который перезаписывается раз в 5 с. Это побочный эффект `write_atomic`.
8. Для `Recover` автосохранение читается, но загрузка в уровень не делается: для OFPA восстановление ограничено предложением (📌, по спеке). Для сцен загрузка появится с форматом EDT-A2.
9. «Cancel» в диалоге означает: редактор работает без автосохранения в этом запуске, существующие файлы и блокировка не трогаются.
10. «Open anyway» берёт блокировку заново. Прямого сравнения pid с живым процессом нет (по спеке, без `unsafe`).
11. Время в статусной строке и в диалоге — UTC, `HH:MM`. Местное время потребовало бы новой зависимости.
12. Страж `atomic_writes` не проверяет код после первой строки `#[cfg(test)]` в файле. Исключение `packager.rs`: это артефакты сборки (бандлы, отчёты), а не состояние редактора. `.bak`-копии бинарников были бы бесполезны.
13. `EditorDock::new()` сохранён как обёртка над `load_or_default(Path::new("editor_layout.ron"), &EditorLog::new())`, чтобы не ломать вызовы.
14. Прописан и Preferences: три поля (`enabled`, интервал, `every_n_transactions`). `keep` в окне не показан, как и просила спека (только три поля).
15. Автосохранение срабатывает только если подключён `scene_path` (`OpenLevel` в приложении). Сейчас приложение открывает только мир, поэтому `is_dirty` всегда `false` и файлы автосохранения не создаются. Пока сцен нет, это ожидаемое поведение.
16. Validator автосохранения сейчас проверяет только, что байты начинаются с `(`. Нормальный валидатор должен быть парсером сцены из EDT-A2.

## 📌 Отложено (с условием)

- **Автосохранение OFPA-мира** (только изменённые актёры в `<мир>/.redox/autosave/...`). Условие: формат OFPA-актёров и `WorldSession` вне этого среза. В приложении источник для мира `is_dirty = false`, поэтому ничего не пишется. Сохраняется только сессионная блокировка, которая пишется в `worlds/<имя>/.redox/session.lock`.
- **Восстановление OFPA-мира** ограничено предложением (по спеке). Загрузка автосохранения в уровень не сделана.
- **Отметка «изменён» после восстановления.** Спека A4 говорит «отмечается изменённым», но в API A3 нет метода для принудительного dirty. Условие: метод вроде `UndoStack::mark_unsaved()` или загрузка сцены через `Level`. Сейчас восстановленный уровень не помечается dirty.
- **Статусная строка «Recovered from autosave».** Поле `recovery_note` есть, но выставляется только после реальной загрузки. Условие то же, что выше.

## ПРЕДПОЛОЖЕНИЯ ОБ API (от других задач волны)

1. `UndoStack::is_dirty(&self) -> bool` (A3, шаг 4). Используется в `app/autosave.rs`: `OpenLevel::is_dirty` и `finish_autosave`.
2. `UndoStack::len(&self) -> usize` (A3, шаг 2). Используется в `tick_autosave` как счётчик транзакций. Это число записей, а не монотонный счётчик: после вытеснения по лимиту 100 оно перестаёт расти, и срабатывание только по времени. Лучше монотонный счётчик в `UndoStack`.
3. `TypeRegistry::to_ron(&self, &World) -> Result<String, ron::Error>`. Уже есть в `redox_reflect/src/lib.rs`. Используется для временного снимка мира.
4. `redox_scene::ofpa::write_atomic(path, &[u8]) -> io::Result<()>`. Уже есть. Используется во всех записях.
5. `EditorContext { world, registry, undo, log, ... }`, `EditorLog::{info,warn,error,lines}`. Уже есть в `redox_editor_core`.
6. Workspace-зависимости `flume`, `ron`, `serde`. Уже есть.
7. `egui::Window`, `egui::Slider`, `egui::Align2`: форма вызовов взята из `command_palette.rs`. `Slider::new(&mut u32, RangeInclusive<u32>)` — проверить при компиляции.

## Ограничения

- Запись `session.lock` при старте создаёт `worlds/<имя>/.redox/`, если каталог мира существует. Это соответствует спеке, но меняет каталог мира на диске.
