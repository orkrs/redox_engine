# План: мир (ландшафт, растительность, вода, атмосфера, декали)

Общий контекст: [PLAN_TECH_OVERVIEW.md](PLAN_TECH_OVERVIEW.md). Опирается на: инстансинг и indirect
(PLAN_GEOMETRY.md, п. 3), граф материалов (PLAN_MATERIALS.md), VG (где применимо), навигацию и физику
(PLAN_PHYSICS_NAV.md). Сейчас в мире есть: разбиение на ячейки (`redox_scene`, `world.bin`, `partition.rs`),
процедурная генерация (`pcg`), небо из HDR + IBL. Ландшафта, растительности, воды, физического неба, декалей нет.

## Что это такое (по пунктам вашего вопроса)

- **Ландшафт (terrain).** Большая поверхность земли, заданная **картой высот** (heightmap): картинка,
  где яркость пикселя = высота. Поверх неё **слои** материала (трава, камень, песок, снег): карта
  смешивания (splatmap) говорит, сколько какого слоя в каждой точке. Нужны LOD (далёкая земля грубее),
  стриминг (земля большого мира подгружается кусками), коллизия и навмеш из того же рельефа.
- **Растительность.** Деревья, кусты, трава, камни в огромном количестве; рисуются инстансингом с LOD,
  ветром, расстановкой по правилам (склон, высота, плотность).
- **Вода.** Океан, озёра, реки: движущаяся поверхность с волнами, пеной, преломлением и отражением,
  глубинным цветом, взаимодействием с физикой (плавучесть).
- **Атмосфера.** Физически правдоподобное небо: цвет зависит от положения солнца, закаты, дымка
  дальних объектов (aerial perspective), облака, смена времени суток.
- **Декали.** Наклейки на поверхности: следы, пятна, выбоины от пуль, граффити, грязь.

## 1. Ландшафт

### 1.1 Данные и формат
- Heightmap плитками (например, 513×513, R16, KTX2 с mip-цепочкой), карты слоёв (splat) и карта
  «отверстий» (пещеры). Всё в `.pak`, читается диапазонами (инфраструктура есть).
- Метаданные: размер мира, масштаб высоты, список материальных слоёв (граф материалов или простые
  параметры), порядок и смешивание.

### 1.2 Рендер
- **Сетка с CDLOD/clipmap**: кольца сеток вокруг камеры, плавная интерполяция вершин между уровнями (geomorphing),
  чтобы не было швов и «скачков». Вершины берут высоту из текстуры в вершинном шейдере (vertex texture fetch).
- **Нормали** из heightmap (по соседним выборкам) или предрасчитанная normal-карта плитки.
- **Материал земли**: высотное смешивание слоёв (height-blend: на выпуклостях побеждает камень), tri-planar для
  отвесных склонов, большие/малые тайлинги против повторений; массив текстур слоёв (`texture_2d_array`).
- **Виртуальные текстуры слоёв** (позднее): для большого количества слоёв и запекания цвета ландшафта.
- Тени: VSM, как для остальных объектов; GI: SDF ландшафта (из heightmap эффективно, отдельный тип SDF).
- Тесты: высота в точке равна значению карты; без швов между плитками и уровнями LOD (сравнение краёв);
  golden-кадры; бенчмарк: мир 4×4 км на RTX 4060 Ti.
- Оценка: 12–16 дней.

### 1.3 Коллизия и навмеш
- Heightfield-коллайдер rapier из той же карты (плитками, подгрузка/выгрузка вместе с рендером);
  источник для запекания навмеша (PLAN_PHYSICS_NAV.md, п. 2.1). 3–4 дня.

### 1.4 Редактирование
- Кисти (поднять/опустить/сгладить/покрасить слой) — в редакторе (этап I). Пока что — импорт heightmap и
  инструмент `redox_cook terrain` для нарезки на плитки.

## 2. Растительность

- **Расстановка (scatter).** Правила: плотность по маске, диапазон высоты и угла склона, минимальное
  расстояние, исключающие зоны (дороги, постройки), случайные вариации масштаба/поворота/цвета с
  фиксированным зерном (детерминированно). Результат — **списки экземпляров по ячейкам**
  (кэшируются в мире), не по одному на сущность.
- **Рендер.** Инстансинг + GPU-отсечение + indirect (PLAN_GEOMETRY.md, п. 3). LOD по расстоянию с
  перекрёстным затуханием (dither), для далёких деревьев — **impostor'ы** (запечённые виды с нескольких углов
  на плоскости), для травы — меши-«пучки» из нескольких лезвий, плотность падает с расстоянием.
- **Ветер.** Анимация в вершинном шейдере (World Position Offset из материала): общий ветер + порывы по
  шуму + вторичное дрожание листьев; маска по цвету вершины (жёсткость).
- **Взаимодействие.** Трава и кусты пригибаются от игрока/существ (буфер «влияний» вокруг камеры).
- **Тени.** Деревья отбрасывают, трава — обычно нет (дорого); настраивается.
- **Материалы листвы.** Masked + двусторонняя подсветка (transmission) (PLAN_MATERIALS.md).
- Тесты: детерминированность расстановки; 100 000 деревьев — время CPU кадра в пределах бюджета; нет
  «мерцания» при смене LOD (сравнение кадров). Оценка: 12–15 дней.

## 3. Вода

- **Типы.** (a) океан/большое озеро: волны на сетке (Gerstner для простоты, FFT для качества);
  (b) реки: карта потока (flow map) задаёт направление течения; (c) малые лужи/пруды: плоскость с
  нормалями и отражением.
- **Рендер.** Сетка clipmap вокруг камеры, смещение вершин волнами; поверхность — прозрачный материал
  с преломлением (цвет фона из копии сцены), **глубинное поглощение** (по разности глубин: у берега
  светлее, в глубине темнее, зависит от длины волны), пена (по гребням и у берега по глубине), отражения
  (SSR + пробы + небо), подводный туман при погружении камеры (постобработка).
- **Физика.** Плавучесть: выборка высоты воды в точках тела (`water_height(x, z, t)` из той же формулы
  волн на CPU), силы Архимеда, сопротивление; всплески (события).
- **Береговая линия.** Прозрачное смешивание с землёй по глубине (depth fade).
- Тесты: высота воды на CPU совпадает с GPU (допуск); тело плавает и успокаивается; кадр без
  артефактов на границе воды и земли. Оценка: 10–14 дней (океан FFT — ещё 5–7).

## 4. Атмосфера

- **Физическое небо** (модель Hillaire): таблицы пропускания, многократного рассеяния и «вида неба»
  (LUT) перерассчитываются при изменении параметров; `sun_direction` из времени суток; цвет солнца и
  неба получаются сами, закаты красные.
- **Aerial perspective**: дымка дальних объектов — froxel-объём (общий с туманом, PLAN_LIGHTING.md, п. 4).
- **Облака**: объёмные, рэймарчинг по 3D-текстурам шума (форма+детали), несколько слоёв, освещение
  солнцем, тень облаков на землю, движение по ветру. Дорогая часть: рендер в четверть разрешения +
  временное накопление.
- **Небо как свет.** Захват неба в кубическую карту в реальном времени (медленно обновляется по
  частям) для IBL и отражений; звёзды и луна ночью.
- **Экспозиция.** Автоэкспозиция (адаптация глаза) от яркости сцены, чтобы закат и полдень
  выглядели правильно.
- Погода: хуки (дождь, снег, туман) через параметры; сами эффекты — частицы и материалы.
- Тесты: цвет неба в зените/на горизонте при высоте солнца 5° и 60° близок к эталону (по
  опубликованным значениям с допуском); сутки без скачков; стоимость кадра в бюджете. Оценка: 12–15 дней.

## 5. Декали

- **Проблема.** У нас forward+visibility-buffer конвейер, а классические «deferred decals» требуют G-buffer.
- **Решение (рекомендую): кластерные декали.** Декали — ориентированные боксы с текстурой из атласа
  (albedo/normal/roughness/opacity); хранятся в списке, привязанном к **той же сетке кластеров, что и огни**
  (`cluster_manager.rs`). В шейдере материала пиксель перебирает декали своего кластера, проецирует
  мировую позицию в пространство декали, читает атлас и подмешивает в поверхность **до освещения**
  (поэтому декаль корректно освещается и получает GI). Плюсы: без дополнительных проходов и буферов;
  минусы: стоимость на пиксель при многих декалях (лимит ~8 на кластер, остальное — отбрасывается).
- Режимы: цвет/нормаль/шероховатость, затухание по углу к поверхности, сортировка по приоритету,
  время жизни (следы пуль исчезают), атлас декалей из KTX2.
- Альтернатива для статичных мест: **меш-декали** (запечённая геометрия), как оптимизация.
- Тесты: декаль на неровной поверхности (проекция правильная), обрезка по боксу, лимит и порядок,
  освещение декали. Оценка: 7–9 дней.

## 6. Порядок и зависимости
инстансинг+indirect (A) → граф материалов (E) → ландшафт → растительность → декали → вода → атмосфера.
Атмосфера и вода можно сдвигать раньше, если нужен быстрый видимый результат (они зависят от материалов
меньше остальных). Итого 8–12 недель.
