# План: материалы и шейдеры (граф материалов, Substrate, SSS, прозрачность)

Общий контекст: [PLAN_TECH_OVERVIEW.md](PLAN_TECH_OVERVIEW.md). Код сейчас: `crates/redox_render/src/material.rs`
(PBR-параметры, текстуры albedo/normal/metallic-roughness, до двух слоёв `MaterialLayer`, sheen),
`asset_types.rs` (`MaterialData`), шейдеры `pbr.wgsl`, `forward.wgsl`, `vg_resolve.wgsl`.

## 0. Что именно мы строим (уточнение понятий)

**Граф материалов — это не «граф рендера».** Это две разные вещи:
- **Граф кадра (render graph)** — порядок проходов рендера (тени → глубина → основной → пост). Он уже
  есть (`frame_graph.rs`, `render_graph.rs`).
- **Граф материалов (material graph)** — редактор узлов, из которого получается **шейдер одного
  материала** (текстуры → математика → слои → выход). Именно он даёт «создание кастомных шейдеров без
  кода». В Unreal это Material Editor. Его мы и строим. Идея «графовой системы в проекте» верна, но
  как отдельная подсистема.

**Substrate** — модель материала «как конструктор»: материал = дерево из независимых оптических слоёв
(slab), каждый со своим BSDF (параметры: цвет, металличность, шероховатость, анизотропия, clearcoat,
sheen, подповерхностное рассеяние, пропускание). Слои комбинируются: **вертикально** (лак поверх краски
поверх металла), **горизонтально** (смесь по маске), **сложением**. Ваше понимание верно.

**SSS (подповерхностное рассеяние)** — уточнение: это **не** «просвечивание сквозь объект». Свет
заходит в материал, рассеивается внутри и выходит рядом с точкой входа: так выглядят кожа, воск, мрамор,
молоко, листья. Их мягкая, «светящаяся изнутри» подсветка и размытая граница теней и есть SSS. А
«свет проходит сквозь объект» (уши на просвет, листья на солнце, шторы) — **пропускание
(transmission/translucency)**. Это разные эффекты, у них разные реализации (ниже).

## 1. Архитектура

### 1.1 Поверхностная функция (рефакторинг первым шагом)
Все шейдеры (основной, VG resolve, прозрачный, теневой с alpha-test, захват для GI) должны получать
поверхность через единую функцию материала:
```
fn material_surface(in: SurfaceInput) -> SurfaceData   // base_color, normal, metallic, roughness, emissive,
                                                      // opacity, слои Substrate, SSS-профиль, ...
```
Сейчас параметры вшиты в `pbr.wgsl`. Шаг M1: вынести их в такую функцию и в структуру материала, сохранив
картинку (golden-кадры не меняются). Оценка 3 дня.

### 1.2 Граф → IR → WGSL
1. **Формат графа** (ассет `.matgraph`, сначала текстовый RON): узлы, типизированные порты, связи,
   параметры (константы и именованные параметры материала).
2. **Проверка**: типы портов, циклы, обязательные выходы; ошибки привязаны к узлу.
3. **Промежуточное представление (IR)**: линейный список операций с типами (float, vec2..4, texture,
   sampler); оптимизации — свёртка констант, удаление мёртвых веток, общий подвыражения.
4. **Кодогенерация WGSL**: функция `material_surface`, выбираемые фичи (набор разрешённых узлов зависит
   от прохода: в теневом проходе нет освещения, в depth-only только opacity).
5. **Варианты шейдера (permutations)**: ключ = (материал, проход, фичи: alpha-test, skinning, instanced,
   vertex animation); кэш скомпилированных модулей на диске; валидация через `naga`; горячая
   перезагрузка при изменении графа (механизм из `ShaderHotReload`).
6. **Параметры без перекомпиляции**: константы, помеченные как параметры, идут в uniform-буфер
   **экземпляра материала** (Material Instance): сотни экземпляров одного графа — один шейдер.

### 1.3 Набор узлов (первая версия)
Входы: UV, мировая позиция, нормаль, направление взгляда, цвет вершины, время, глубина сцены.
Текстуры: sample 2D/массив/куб (через реестр текстур и будущие bindless-индексы), triplanar, парралакс.
Математика: арифметика, `lerp`, `clamp`, `pow`, `dot`, `normalize`, `fresnel`, шум (value/gradient/worley),
градиенты, `if` по маске. Утилиты: нормаль из высоты, распаковка normal map, height-blend, мировые
UV. **Custom node**: фрагмент WGSL пользователя с объявленными входами/выходами (проверяется компиляцией).
Вывод: `Substrate Slab`, `Layer`, `Mix`, `Material Output`. Vertex-часть: смещение позиции (ветер,
волны) — **World Position Offset**.

## 2. Substrate (слои)

- **Slab** (параметры): base_color, metallic, specular/F0, roughness, anisotropy+tangent, normal, emissive,
  clearcoat (вес, шероховатость, нормаль), sheen (цвет, шероховатость), SSS (профиль, радиус, вес),
  transmission (цвет, толщина), thin film (опционально).
- **Операторы**: `Vertical(coat, base)`, `Horizontal(a, b, mask)`, `Add(a, b)`, `Weight(slab, w)`.
- **Вычисление.** Для каждого слоя считается вклад BSDF; слои сверху ослабляют нижние по энергии
  (закон сохранения: прошедший свет = 1 − отражённое слоем). Для простых материалов (один slab) —
  быстрый путь без цикла по слоям; сложные — до N слоёв (лимит, например, 3 в первой версии).
- **Классификация пикселей** (как в Unreal): тайл знает, какие материалы в нём (простые/сложные), чтобы
  не платить за сложность там, где она не нужна. Первая версия: классификация по материалу в VG resolve
  (бининг), в forward — по варианту шейдера.
- **Совместимость.** Существующий `Material` (PBR + 2 слоя + sheen) = частный случай Substrate;
  миграция сохраняет внешний вид (golden-кадры).
- Тесты: энергосбережение (альбедо ≤ 1 при любых параметрах), clearcoat даёт второй блик, сравнение со
  справочными изображениями (шар с параметрами), стабильность на крайних значениях шероховатости.
- Оценка: 8–10 дней.

## 3. SSS

Реализуем по возрастанию стоимости:
1. **Wrap-освещение** («дешёвое SSS», мягкое терминатор): 1 день, для листьев/тканей.
2. **Экранное разделяемое SSS** (Jimenez): для пикселей с SSS-профилем диффузное освещение пишется
   в отдельный буфер, размывается в экране двумя проходами (горизонт/вертикаль) ядром, зависящим от
   профиля (цвет рассеяния: красный дальше, синий ближе), затем складывается со спекуляром. Нужны:
   профиль рассеяния как ассет (`SubsurfaceProfile`), маска материала, учёт глубины (чтобы не размывать
   через края). Оценка 6–8 дней.
3. **Пропускание на просвет** (тонкие объекты): оценка толщины по карте толщины или по теневой глубине,
   свет проходит с цветным затуханием. 3 дня.
- Тесты: сфера «кожи» на солнце имеет мягкий терминатор с красноватой границей; края силуэта не
  размыты; кадр без SSS-пикселей не платит за проходы (счётчик/таймер).

## 4. Прозрачность и пропускание

| Режим | Что | Как |
|---|---|---|
| Opaque | непрозрачное | основной путь (forward/VG) |
| Masked | альфа-тест (листва, заборы) | вариант шейдера с `discard`; теневой вариант тоже |
| Dithered / hashed | «псевдопрозрачность» без сортировки | порог по шуму, сглаживается TAA/TSR; для LOD-переходов |
| Translucent | стекло, вода, дым | отдельный проход после непрозрачного, сортировка объектов по глубине, освещение по кластерам, приём теней |
| Additive | огонь, магия | без сортировки |
| Refraction | преломление толстого стекла | копия цвета сцены (с mip-цепочкой для шероховатости), смещение UV по нормали и IOR |
| OIT (опционально) | независимая от порядка прозрачность | weighted blended для частиц и множества слоёв |

- Взаимодействие с TAA/TSR: прозрачные поверхности пишут реактивную маску и (по возможности) скорость.
- Тесты: стекло перед объектом не ломает глубину; сортировка устойчива; тени от прозрачного (по
  непрозрачности); golden-кадры.
- Оценка: 8–10 дней.

## 5. Кастомные шейдеры и материалы

- **Custom node** (раздел 1.3) и **полностью свой материал**: пользователь пишет WGSL-функцию
  `material_surface` по заданному интерфейсу; движок оборачивает проходами и вариантами.
- Ошибки WGSL показываются с номером строки в узле/файле; изменения подхватываются горячей перезагрузкой.
- Безопасность и скорость: лимит сложности (число текстурных выборок и инструкций) с предупреждением;
  отключение дорогих фич по уровню качества.
- Оценка: входит в этапы 1.2–1.3.

## 6. Интеграция с остальными подсистемами
- **VG**: resolve-проход вызывает `material_surface` корзины материала (PLAN_GEOMETRY.md, п. 1.4).
- **GI**: захват в поверхностный кэш использует выходы albedo/emissive/normal (PLAN_LIGHTING.md, G2).
- **Тени**: теневой вариант с alpha-test/WPO; **скорость**: вариант с WPO для точной скорости.
- **Скиннинг/инстансинг**: ключи вариантов шейдера.
- **Редактор**: узловой редактор и превью материала — в этапе редактора; до того граф правится в
  текстовом формате с горячей перезагрузкой.

| M7 | интеграция VG/GI/тени/скорость | нет регрессий, варианты кэшируются | 6–8 дней |

## 8. Риски
- Взрыв числа вариантов шейдера и время компиляции → ключ вариантов минимален, дисковый кэш, прогрев.
- Слои Substrate дороги → быстрые пути для простых материалов, лимит числа слоёв, классификация.
- Отладка сгенерированного кода → вывод WGSL по запросу, карта «узел → строка».
