## Решения, принятые на сегодня

1. Только Windows + Vulkan (другие ОС и GPU вырезаны из плана).
2. Скриптинг: WebAssembly ([ADR 0005](adr/0005-scripting-wasm.md)). **Чистый Rust остаётся**: движок
   и основной игровой код на Rust (как у Bevy), WASM — встроенный изолированный слой для логики,
   модов и горячей перезагрузки. Подробности в PLAN_SCRIPTING.md.
3. Сначала доводим технологии, потом редактор и стабильный API (порядок и оговорки — ниже).
4. Визуальная цель: «современный» уровень (виртуальная геометрия, глобальное освещение, виртуальные
   тени), но не паритет с Unreal; нишевая позиция — Rust-нативный data-oriented движок.

## Порядок работ и почему именно такой

Принцип: сначала то, что **меняет форму API и данных** (после него всё остальное строится),
потом большие визуальные куски, потом инструменты. Каждая фаза заканчивается тестами и живой
проверкой на Courier или новом тестовом стенде.

| Этап | Что | Почему сейчас | Оценка |
|---|---|---|---|
| A. Фундамент GPU и данных | per-object velocity (чинит TAA), GPU-скиннинг, инстансинг + indirect draw, бюджеты памяти (общий каркас) | от этого зависят вегетация, ландшафт, VG, апскейл; чинит видимые дефекты | 3–4 недели |
| B. Игровой слой | физика (касты, overlap, слои, joints), WASM-хост и API, аудио-доработки | нужна любой игре; формирует API | 4–6 недель |
| C. Быстрые визуальные победы | тени статика/динамика, SSR + пробы отражений, объёмный туман (froxel), DoF, motion blur, TSR/FSR | высокий визуальный эффект при умеренной цене | 4–6 недель |
| D. Виртуальная геометрия | иерархия кластеров (DAG), стриминг, HLOD, программный растеризатор мелких треугольников | основа больших миров | 6–10 недель |
| E. Материалы | граф материалов, Substrate-слои, SSS, transmission, кодогенерация WGSL | нужен до ландшафта и воды | 6–8 недель |
| F. Мир | ландшафт, вегетация, вода, атмосфера, декали | опирается на A, D, E | 8–12 недель |
| G. Глобальное освещение | SDF/surfel/радиус-кэш, трассировка, опционально аппаратные лучи | самое дорогое; выигрывает от готовых D и E | 8–14 недель |
| H. Навигация | navmesh, A*, избегание | независима, можно в любой момент после B | 3–5 недель |
| I. Редактор и стабильный API | редактор как инструмент, заморозка API, документация | строится на готовых системах | 3–6 месяцев |

Сроки грубые, для одного разработчика, без учёта неожиданностей; по ходу пересматриваются.

### Оговорка про «сначала технологии, потом редактор»

Идти так можно, но с двумя поправками:
- **Не «до идеала»**, а до рабочего уровня с тестами и замером: бесконечная полировка технологий без
  использования в игре — главный риск для проекта одного человека. Каждый этап должен быть виден в
  Courier или другом стенде.
- **Минимум инструментов нужен раньше**: графу материалов, ландшафту и вегетации нужно хоть какое-то
  окно для правки (иначе всё задаётся кодом). Поэтому редактор растёт кусками внутри этапов E и F
  (превью материала, кисти ландшафта), а этап I — это доведение и заморозка API.
- API замораживаем только в конце: до этого он должен свободно меняться.

## Словарь

- **Draw call** — команда видеокарте нарисовать объект; тысячи таких команд грузят процессор.
- **Indirect draw** — команда рисования, параметры которой лежат в буфере на GPU и заполняются самим
  GPU (например, после отсечения), без участия CPU.
- **Instancing** — один меш рисуется многократно за один вызов, у каждого экземпляра свои данные.
- **Meshlet / кластер** — маленький кусок меша (64–128 треугольников); единица отсечения и LOD в VG.
- **HLOD** — иерархические LOD для мира: далёкая группа объектов заменяется одним упрощённым прокси.
- **Visibility buffer** — вместо цвета в буфер пишется «какой треугольник виден», шейдинг делается позже.
- **GI** — глобальное освещение: свет, отражённый от поверхностей и освещающий другие поверхности.
- **SDF** — поле расстояний со знаком: для каждой точки хранится расстояние до ближайшей поверхности.
- **Surfel** — маленький диск на поверхности, хранящий освещённость; облако таких дисков — кэш света.
- **Froxel** — воксель в пирамиде видимости камеры; сетка froxel нужна для объёмного тумана.
- **TAA / TSR** — временное сглаживание / временное повышение разрешения (накопление кадров).
- **Substrate** — модель материала из независимых слоёв (как в Unreal 5.x), каждый со своим BSDF.
- **BSDF** — функция, описывающая, как поверхность рассеивает свет.
- **SSS** — подповерхностное рассеяние: свет заходит в материал и выходит рядом (кожа, воск, мрамор).
- **Navmesh** — полигональная сетка проходимых мест для поиска пути.
- **RVO / ORCA** — алгоритмы избегания столкновений агентов друг с другом.
- **Граф кадра (render graph)** — порядок проходов рендера (уже есть). **Граф материалов** — это другое:
  редактор узлов, из которого получается шейдер материала.

## Общие требования к каждой задаче в планах

- Тесты на уровне данных (юнит) и, где есть GPU, GPU-тесты с проверкой ошибок валидации.
- Бенчмарк или GPU-таймер: каждая оптимизация подтверждается измерением до/после.
- Критерий «готово» записан до начала работы.
- Обновление `ARCHITECTURE_REALITY.md`, `PROGRESS.md`, `CHANGELOG.md`; ADR при выборе из вариантов.
- Живой тест на Courier (или новом стенде) глазами владельца: скриншоты не делаются без разрешения.
