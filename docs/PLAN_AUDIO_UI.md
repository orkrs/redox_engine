## Часть 1. Аудио

### Что есть
Крейт `redox_audio` на `kira` 0.12: `AudioContext`, миксер с шинами (`mixer.rs`: Music, SFX, Voice, Ambient —
`all_sub_buses`, громкость и mute), пространственный звук (`spatial.rs`), ассеты звуков (`loader.rs`),
отладочный оверлей, компоненты аудио-эмиттеров.

### Что делаем и зачем

#### 1.1 Стриминг музыки
- **Зачем.** Музыка — десятки МБ; декодировать целиком в память дорого. Стриминг читает и декодирует по
  кускам.
- **Как.** Проверить, что `kira` предоставляет потоковый источник (`StreamingSoundData` с декодером
  symphonia) и совместим с нашим `AssetSource` (чтение из `.pak` по диапазонам). Форматы: Ogg Vorbis
  и Opus (музыка), WAV/FLAC (короткие эффекты в памяти). Буферизация с запасом, паузы без щелчков,
  зацикливание с точкой возврата, кроссфейд между треками.
- **Тесты.** Поток не прерывается при нагрузке чтения; память ограничена; переключение треков без щелчка
  (анализ сигнала); повреждённый файл не роняет игру.
- **Оценка:** 3–4 дня.

#### 1.2 Адаптивная музыка
- **Слои (stems):** несколько синхронных дорожек, включаемых по состоянию игры (спокойно → бой).
- **Горизонтальная пересборка:** переходы между секциями по границе такта/доли (нужны BPM и сетка в
  метаданных трека), «стингеры» (короткие акценты поверх).
- **Данные:** ассет `MusicCue` (треки, слои, правила переходов), параметры (`intensity`, `state`).
- **Оценка:** 5–6 дней.

#### 1.3 Граф эффектов (шины и эффекты)
- **Шины с цепочкой эффектов:** reverb, эквалайзер, фильтры низких/высоких частот, компрессор, дилей;
  посылы (sends) на общий reverb.
- **Снимки микса (snapshots):** состояния («пауза» — музыка глуше через low-pass, «подводный» —
  фильтр + reverb) с плавными переходами.
- **Ducking:** музыка приглушается, когда говорит голос (сайдчейн по активности шины Voice).
- **Громкость в децибелах** и единые кривые для пользовательских настроек (master/music/sfx/voice) с
  сохранением в `SaveManager`.
- **Оценка:** 6–8 дней (зависит от возможностей `kira`; недостающее — свои эффекты).

#### 1.4 Пространственный звук 2.0
- Окклюзия **по физике** (лучи через `redox_physics` — нужны касты и слои, PLAN_PHYSICS_NAV.md, п. 1),
  зоны реверберации (есть заготовки), доплер, кривые затухания (линейная/лог/пользовательская), приоритеты
  и **виртуализация голосов** (дальние тихие звуки не играются, но «помнят» положение).
- **Оценка:** 5–7 дней.

#### 1.5 Звуковые события (`SoundCue`)
- Ассет данных: набор вариантов (случайный выбор без повторов подряд), диапазоны высоты/громкости,
  cooldown (не чаще раза в N мс), приоритет, шина. Вызов по имени: `play_cue("footstep_grass")`,
  из WASM — тот же вызов. Шаги по материалу поверхности (событие клипа анимации → cue по
  физическому материалу под ногой).
- **Оценка:** 3–4 дня.

#### 1.6 Инструменты
- Оверлей: активные голоса, уровни шин, VU-метры, стоимость CPU. Тест-стенд: проигрывание cue из
  командной строки. 2–3 дня.

**Порядок аудио:** SoundCue → стриминг музыки → шины и эффекты → адаптивная музыка → окклюзия по
физике. Итого 4–5 недель.

## Часть 2. Игровой UI

### Что есть
`redox_ui::game`: дерево виджетов (колонка, ряд, стек, метка, кнопка, полоса), раскладка в виртуальном
1920×1080 с безопасной зоной, локализация RU/EN с падежами, навигация фокусом, стек экранов, отрисовка
через egui (`paint.rs`). egui остаётся для отладки и редактора.

### Решение по отрисовке (главное)
**Игровой UI получает собственный рендер-бэкенд** (в `redox_render`/отдельный модуль) вместо egui:
- Причины: egui — для инструментов (иммедиат-режим, свой стиль, зависимость обновлений от egui); игре
  нужны полный контроль над стилем, батчинг, анимации, мировые UI, скорость и независимость от egui
  при поставке.
- Что берём: пакетная отрисовка прямоугольников (скругление, обводка, градиент, тень, 9-slice,
  текстуры из атласа), **текст** через `cosmic-text` (раскладка, шрифты, fallback, RTL позже) + атлас
  глифов (или SDF/MSDF для чёткого масштабирования), клиппинг (scissor), прозрачность и порядок слоёв.
- Egui-бэкенд остаётся как запасной/отладочный (раскладка и логика не меняются — они независимы).
- Тесты: golden-кадры экранов; метрики текста (ширина строки) совпадают между раскладкой и рендером;
  кириллица и эмодзи-подстановка; производительность: 5 000 виджетов < 1 мс CPU.
- Оценка: 10–14 дней.

### Виджеты
Картинка/иконка, слайдер, переключатель (toggle), выпадающий список, **поле ввода текста** (каретка,
выделение, копирование, IME через `redox_input::text`), прокручиваемая область, список/сетка,
вкладки, подсказка (tooltip), модальное окно, индикатор прогресса (круговой), полоса здоровья в мире.
Каждый — данные + поведение + тесты фокуса/клавиатуры/мыши. Оценка: 10–14 дней.

### Раскладка
Расширение до flex-подобной: grow/shrink/basis, перенос строк (wrap), min/max размеры, выравнивание и
отступы, пропорции (aspect), абсолютное позиционирование, привязка к краям (есть), прокрутка. Тесты на
сложных деревьях и экстремальных размерах окна (4:3, 21:9, 720p…4K). Оценка: 5–6 дней.

### Стили и темы
Файл темы (`.ron`): цвета, шрифты, размеры, скругления, состояния (normal/hover/pressed/focus/disabled),
наследование стилей по классу (`class: "primary-button"`), смена темы на лету. Оценка: 4–5 дней.

### Анимация UI
Твины (easing: linear/ease/spring), переходы появления/скрытия экранов, пульсации фокуса, анимации
чисел (счётчики), последовательности. Оценка: 4–5 дней.

### Данные и привязка к игре
Экраны описываются файлами (`.ron`), горячая перезагрузка; привязка значений к ресурсам ECS и событиям;
вызов из WASM (PLAN_SCRIPTING.md): `ui_open("pause")`, `ui_set("coins", 5)`, события кнопок.
Оценка: 5–6 дней.

### Мировой UI и рендер-в-текстуру
Полосы здоровья/подписи над объектами (billboard в мировых координатах, масштаб по расстоянию, отсечение
за экраном), UI на поверхностях (рендер в текстуру → материал). Оценка: 4–5 дней.

### Локализация и доступность
- Правила множественных чисел для большего числа языков (поднабор CLDR), форматирование чисел/дат/
  времени, шрифты по языкам (CJK — отдельные файлы с подстановкой), смена языка на лету (есть).
- Доступность: масштаб UI, высокий контраст, размер текста, навигация без мыши (есть), режим для
  дальтоников (замена цветовых сигналов формой/иконкой).
- Оценка: 5–6 дней.

### Порядок UI
собственный бэкенд и текст → виджеты → раскладка → стили → анимации → данные/WASM → мировой UI →
локализация/доступность. Итого 6–8 недель.
