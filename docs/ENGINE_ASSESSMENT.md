# RedOx Engine: состояние, сравнение с Godot / Unity 6 / Unreal 5 и план выхода на рынок

Дата среза: 2026-10-16. Источники: код репозитория (обзор четырёх разведчиков + мои проверки),
собственные знания о конкурентах. **Данные о Godot, Unity 6 и Unreal 5 не сверялись с интернетом
и могли устареть: перед внешним использованием проверьте их по официальным страницам.**
Оценки зрелости и сроки — экспертные прикидки, не измерения.

## 3. Оценка прогресса (экспертная)

| Область | Готовность относительно «шипящегося» движка общего назначения |
|---|---|
| ECS и ядро | ~60 % |
| Рендер: ядро конвейера | ~55 % |
| Рендер: набор возможностей (паритет с UE/Unity) | ~25 % |
| Анимация | ~30 % |
| Физика | ~30 % |
| Аудио | ~50 % |
| Редактор | ~20 % |
| Скриптинг / UI / сеть / навигация | 0–10 % |
| Платформы и упаковка | ~5 % |
| Инфраструктура (CI, лицензии, релизы) | ~10 % |
| **Итого** | **≈ 15 %: сильная технологическая демонстрация (pre-alpha), не продукт** |

Сильные стороны: собственный ECS, полностью управляемые GPU тени (VSM), VG-конвейер, профайлер и
эталонные кадры (редкость для молодых движков), честная документация состояния, быстрая итерация.
Главные слабости: ширина (нет UI, скриптинга, сети, платформ), устаревшие зависимости, один
разработчик против больших команд, ничего не опубликовано.

## 4. Реалистичная цель

Паритет «во всём» с Unreal и Unity нереален для малой команды: у них сотни разработчиков и десятки лет.
Движок выходит на рынок не лобовым сравнением, а нишей. Предлагаемая позиция:

> **Rust-нативный, data-oriented 3D-движок для разработчиков, которым важны производительность,
> предсказуемость и код как источник истины** (технические инди и AA, симуляции, инструменты).

Вехи: **0.1** (вертикальный срез для Rust-разработчиков) → **0.5** (редактор + игровой UI +
скриптинг, можно делать небольшие игры) → **1.0** (стабильный API, платформы, документация,
примеры полноценных игр).

## 5. План по порядку

Сроки — грубые, для 1–2 разработчиков; отмечено, что даёт каждый этап.

### Этап 0. Гигиена (2–4 недели)
1. Положить файлы лицензий (MIT и Apache-2.0, как заявлено), поле `license` в `Cargo.toml`.
2. CI (GitHub Actions): `fmt`, `clippy -D warnings`, `cargo test`, golden-кадры на программном
   адаптере (WARP / lavapipe) либо на GPU-раннере; `cargo deny`, `cargo audit`.
3. Закоммитить всё (сейчас ~90 файлов вне git), очистить корень (`Новая папка`, `report.json]`,
   `tmp_bits.pdb`, `local_full_render.md`), `rust-toolchain.toml`, `rustfmt.toml`.
4. Удалить мёртвый код: путь CSM, `shadow/visibility.rs`, `shadow/local_light.rs`, неподключённые
   шейдеры. Разбить файлы больше 800 строк (`frame.rs`, `vsm_clipmap.rs`, `init.rs`, `main.rs` редактора).
5. Привести документы к факту (README, PROJECT_MAP, ARCHITECTURE_REALITY) и сделать их проверяемыми.
6. Аудит `unsafe` в `redox_ecs` (около 70 мест): SAFETY-комментарии, Miri/loom-тесты.

### Этап 1. Фундамент рантайма (2–3 месяца)
1. **Обновление зависимостей** отдельными ветками: wgpu 0.20 → актуальная, winit 0.29 → 0.30+, rapier,
   kira, egui. Чем позже, тем дороже.
2. **Render graph** и управление ресурсами: автоматические барьеры, переиспользование временных
   текстур, пайплайн-кэш, шейдерные модули без копипасты (сегодня VSM-код зеркалится в 4 файла).
3. **ECS до конца:** отложенные команды, мутирующие параллельные запросы, системные наборы,
   run-условия, derive-макрос для Reflect.
4. **Ассеты:** стабильные GUID, зависимости между ассетами, выгрузка по счётчику ссылок,
   сжатые текстуры (KTX2/BC/ASTC), потоковая загрузка, cooking.
5. **Сохранения и ввод:** общий save/load, ремаппинг, геймпады.
6. **Кроссплатформенность:** Linux и macOS (Vulkan/Metal), затем веб (WebGPU).

### Этап 2. Игровой рантайм (3–4 месяца)
1. **Скриптинг/логика:** решить стратегию. Реалистично: Rust с горячей перезагрузкой через динамическую
   библиотеку как основной путь + встраиваемый язык (Lua или WASM) для дизайнеров.
2. **Анимация:** state machine, blend tree / blend space, root motion, слои и маски, события клипов,
   ретаргетинг; GPU-скиннинг и скиннинг нормалей.
3. **Физика:** joints, слои коллизий, shape-cast и overlap-запросы, ragdoll, дебаг-рисование.
4. **Игровой UI:** retained-mode тулкит (раскладка, текст со шрифтами, локализация), а не только egui.
5. **Навигация:** navmesh (рекаст-подобный), pathfinding, avoidance.
6. **Мир:** ландшафт (heightmap + слои), растительность, вода, процедурная атмосфера, декали.
7. **Аудио:** стриминг музыки, граф эффектов.
8. **Сеть:** базовая репликация сущностей поверх ECS (клиент-сервер, предсказание на втором шаге).

### Этап 3. Паритет по рендеру (непрерывно, 6+ месяцев)
1. Довести тени: разделение статики/динамики в VSM (убрать полную перерисовку страниц под
   анимацией), VSM для точечных и прожекторных ламп, стабильность на больших мирах.
2. **GI:** настоящий непрямой свет без RT (воксели/SDF/surfel-пробы), затем опциональный аппаратный RT.
3. **Отражения:** SSR + пробы отражений, объёмный туман и лучи света, DoF, motion blur.
4. **Апскейл:** FSR/DLSS/XeSS через плагины, нормальный TSR.
5. **Материалы:** граф материалов, clearcoat, анизотропия, подповерхностное рассеяние, transmission.
6. **Геометрия:** стриминг VG, иерархия LOD, окклюзия; GPU-driven инстансинг и батчинг обычных
   мешей (сейчас отдельный draw call на объект).
7. **Оптимизация:** async compute, снижение стоимости cluster-cull (~0,5 мс из ~2 мс в простой сцене),
   бюджеты по проходам и автоматические бенчмарки в CI.

### Этап 4. Редактор как продукт (6–9 месяцев)
Префабы и вложенные сцены, браузер ассетов с настоящими миниатюрами, редактор материалов и анимаций,
инструменты ландшафта, PIE на настоящем рантайме с горячей перезагрузкой, единый undo во всех
панелях, API плагинов редактора, шаблоны проектов, конвейер экспорта (сборка, упаковка, подпись).

### Этап 5. Выход на рынок
1. Вертикальный срез (1–2 небольшие игры на движке) как доказательство.
2. Документация, туториалы, сайт, примеры; семантические версии и политика совместимости.
3. Лицензия и модель монетизации (open-source ядро + платные плагины/поддержка — типичный путь).
4. Сообщество (Discord, issue-трекер, roadmap), магазин ассетов.
5. Консоли — только через партнёрские SDK и порты; планировать после стабильного 1.0.

## 6. Риски и как их снижать
| Риск | Снижение |
|---|---|
| Размах задач против размера команды | Нишевая позиция, жёсткий scope по вехам, не гнаться за паритетом UE |
| Отставание зависимостей (wgpu, winit, egui) | Регулярное обновление, CI, изоляция слоёв |
| Привязанность к Windows | Linux/macOS на этапе 1, CI на трёх ОС |
| «Bus factor» (один разработчик) | Документация, тесты, ADR-заметки, приём внешних PR |
| Конкуренты бесплатны (Godot, Unity, UE) | Фокус на то, чего у них нет: Rust, предсказуемая производительность, прозрачный код |
