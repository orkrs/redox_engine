# RedOx Engine — реальная архитектура (as-built)

> Сверено с кодом 2026-10-17. Источник истины для порядка кадра —
> `crates/redox_render/src/renderer/frame.rs`; тот же порядок продублирован как декларация в
> `crates/redox_render/src/frame_graph.rs`, а тест `declared_passes_match_the_hand_written_frame`
> падает, если они разошлись. Прежняя версия документа (wgpu 0.20, CSM, VSM «optional») удалена:
> она описывала код августа 2026 года и осталась в истории git.

## Что это

Рендерер: forward-пайплайн с кластерным светом, Virtual Geometry (meshlet'ы, visibility-буфер)
и виртуальные карты теней (VSM) как единственный источник прямых теней. Каскадные карты теней
(CSM) удалены. Всё на wgpu 30 и WGSL; окно — winit 0.30.


Граф зависимостей генерируется: `docs/CRATES.md`.

## Кадр: порядок проходов

Метки совпадают с GPU-профайлером (`gpu_profiler.mark`) и с `frame_graph.rs`.
Часть проходов условна (например, VG-resolve только при включённой Virtual Geometry).

| # | Проход | Что делает |
|---|---|---|
| 1 | `shadow_passes` | запрошенные страницы VSM и точечные тени |
| 2 | `ddgi_fill` | обновление проб DDGI (заполняются на CPU, семплируются на GPU) |
| 3 | `cluster_vg_cull` | кластерное отсечение света, фаза 1 отсечения VG |
| 4 | `normal_prepass_hiz` | глубина + нормали, пирамида Hi-Z |
| 5 | `gtao` | GTAO в половинном разрешении, размытие, апсемплинг |
| 6 | `vsm_screen_shadow` | экранная маска теней из VSM |
| 7 | `forward` | непрозрачный PBR (с субстрейт-слоями) в HDR `Rgba16Float` |
| 8 | `vg_visibility_resolve` | VG: visibility-буфер → полноэкранный resolve |
| 9 | `transparent` | прозрачные объекты, глубина только для чтения |
| 10 | `msaa_resolve_particles` | MSAA-resolve, затем GPU-частицы |
| 11 | `scatter_light` | стохастический путь точечных света (режим ScatterLight) |
| 12 | `taa_tonemap_bloom_smaa` | bloom, velocity, TAA/TSR, тонмаппинг, SMAA |
| 13 | `frame_tail` | копия глубины для TAA следующего кадра, чтение результатов VG-отсечения, снимок view-proj, отправка очереди |

Порядок исполнения берётся из скомпилированного графа: `render_frame_into` вызывает
`frame_pass_order()` и для каждого имени запускает метод `pass_*` (`run_frame_pass` в `frame.rs`),
после чего ставит GPU-метку с тем же именем. Подготовка буферов, джиттер TAA и список грязных
страниц VSM выполняются до проходов (`begin_frame_state`), отправка очереди — после (`finish_frame`).

Ресурсы между проходами объявлены в `frame_graph.rs`. Вывод компилятора графа:
ни один проход не отсекается; транзиентные текстуры сейчас не делят память (форматы различаются
или времена жизни пересекаются), поэтому выигрыша от алиасинга в этом кадре нет.

## Что работает и как проверено

| Область | Статус | Проверка |
|---|---|---|
| Кадр целиком | рисуется на RTX 4060 Ti (Vulkan) | `skinned_demo --golden`: 3 эталонных кадра, ошибка 0.01–0.07 |
| Тени | только VSM | golden-кадры, юнит-тесты `vsm_clipmap` |
| Кэш пайплайнов | Vulkan: файл ~1 МБ пишется и читается заново | два запуска демо, лог «pipeline cache installed … bytes loaded» |
| DX12/Metal | кэш недоступен (`None`), остальное как раньше | не проверялось на этих бэкендах |
| ECS | тесты, property-тесты, Miri | Miri не покрывает тесты с rayon, trybuild и счётчик аллокаций |
| Ассеты | GUID, pak v2 (LZ4, чтение диапазонов), счётчики ссылок, зависимости, приоритетная очередь, KTX2 (Zstd, Basis, кубы, массивы), стриминг mip | `crates/redox_asset/tests/` |
| Ввод | контексты, геймпады (gilrs), текст/IME | юнит-тесты; живой геймпад и IME не пробовались |
| Анимационный граф | параметры, state machine, blend tree 1D, слои с маской, root motion, события | `redox_anim::graph` (9 тестов), пример `courier` |
| Игровой UI | раскладка, масштаб, локализация RU/EN с падежами, фокус, стек экранов, отрисовка через egui | `redox_ui::game` (18 тестов), `courier` (раскладка экранов во всех окнах и языках) |
| Стриминг текстур | `TextureStreamer`: нижние mip сразу, mip по размеру на экране, бюджет памяти | 5 GPU-тестов, golden-кадр сошедшегося стриминга, `courier` |
| Ресайз окна | пересоздаёт текстуры; привязки тонмаппинга перепривязаны к новому bloom | `resize_bloom` (3 режима AA) |

## Известные ограничения

- DDGI не использует трассировку лучей: пробы заполняются на CPU (направленный свет + небо/земля).
- SDF-страницы — запечённые демо-кирпичи, не привязаны к стримингу сцены.
- Скиннинг — на CPU; GPU-скиннинга и normal map для скинов нет.
- Порядок проходов задаёт граф, но зависимости текстур в нём объявлены вручную и не выводятся из кода проходов;
  память транзиентных текстур по графу не выделяется (проходы владеют своими текстурами).
- Горячая перезагрузка шейдеров (`ShaderHotReload`, feature `shader-hot-reload`) пересобирает 13 групп
  проходов; compute-часть VG и IBL требуют перезапуска.
- Редактор и примеры `dino_runner`, `dino_game` после перехода на wgpu 30 запускались только на уровне сборки и
  коротких прогонов; `courier` и `skinned_demo` проверены вживую. Скиннинг-риг в Courier процедурный, из glTF в граф
  анимации данные пока не грузятся.
- CI-конфигурация лежит в `.github/`, но ни разу не запускалась и пока не используется.
